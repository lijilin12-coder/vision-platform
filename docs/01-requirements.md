## 1. 背景与目标

见 [ddd/00-vision.md](ddd/00-vision.md)。简述：

- **可编排**：算法做成可以自由组合的算子，拖拽搭出检测方案。
- **跨平台**：方案与平台无关，在鸿蒙电脑、Linux、Windows 上都能编辑和运行，结果一致。
- **数据闭环**：采图、数据集、标注、导出给外部训练。
- **模型工具链**：导入、量化、转换、验证、发布。
- **不停机**：热启动；上线包热切换，可回滚。

项目同时是学习项目，目标是 2027 年夏秋参加鸿蒙类比赛、2028 年春参加计算机设计大赛或服务外包大赛（见 [05-roadmap.md](05-roadmap.md)）。

## 2. 用户角色

| 角色 | 代码名 | 主要活动 |
|---|---|---|
| 方案开发者 | `RecipeDesigner` | 搭建、调试、发布方案；组装上线包；部署；标定；管理数据集和模型 |
| 操作员 | `LineOperator` | 启动和停止工位、查看结果、复判 |
| 算子开发者 | `OperatorDeveloper` | 开发和测试算子 |

三个角色在所有运行平台上都能工作。

## 3. 平台

| 类别 | 平台 | 优先级 |
|---|---|---|

| 开发机 | macOS（Apple Silicon），不作为正式发布平台 | — |

## 4. 功能需求

优先级：**P0** = POC / MVP 必须有；**P1** = 第一次参赛前完成；**P2** = 加分项。
编号前缀对应限界上下文。

### 4.1 BC-1 算子目录

| 编号 | 需求 | 优先级 |
|---|---|---|
| CAT-01 | 启动时注册所有算子；ID 冲突或元数据不合法时报错 | P0 |
| CAT-02 | 算子元数据：ID、主版本号、名称、分类、端口定义、参数定义 | P0 |
| CAT-03 | 算子测试页面：单独对一个算子输入测试图，查看输出和耗时 | P1 |
| CAT-04 | 脚本算子：不重新安装程序就能新增算子 | P2 |

### 4.2 BC-2 方案编排

| 编号 | 需求 | 优先级 |
|---|---|---|
| AUT-01 | 创建方案；添加、删除节点；连线、断开 | P0 |
| AUT-02 | 编辑时随时保证不变量 R1～R6（无环、类型兼容、单入线、参数合法、具名区域引用、删除节点同时删除连线） | P0 |
| AUT-03 | 自动生成参数面板（根据算子参数定义） | P0 |
| AUT-04 | 调试运行：查看任一节点的中间结果 | P0 |
| AUT-05 | 发布方案版本；发布时检查规则 P1～P5 | P0 |
| AUT-06 | ROI：绝对 ROI | P0 |
| AUT-07 | ROI：相对 ROI（定位跟随）、具名区域 | P1 |
| AUT-08 | 声明模型依赖（模型 ID + 主版本号）、声明标定需求 | P1 |
| AUT-09 | 匹配模板创建 | P1 |
| AUT-10 | 升级节点算子（算子大版本升级时迁移参数） | P1 |
| AUT-11 | 停用方案版本 | P1 |
| AUT-12 | 大模型辅助生成方案 | P2 |

### 4.3 BC-3 检测执行

| 编号 | 需求 | 优先级 |
|---|---|---|
| EXE-01 | 方案版本编译成执行计划（拓扑排序、绑定输入输出、实例化算子） | P0 |
| EXE-02 | 执行检测，记录每个节点的状态和耗时；节点失败时下游跳过，判定为 ERROR | P0 |
| EXE-03 | 检测结果包含缺陷、测量值、位姿三类结果项；判定附带判定依据 | P0 |
| EXE-04 | 三种用途：调试、产线、检查（验收和一致性）；调试不发布“检测已完成” | P0 |
| EXE-05 | 推理节点：异常检测（优先）、分类 | P1 |
| EXE-06 | 测量节点：卡尺边缘（亚像素）、直线和圆拟合、距离和角度，按标定换算为毫米 | P1 |
| EXE-07 | 多图像检测（多相机、多光源） | 待定（H-11） |

### 4.4 BC-4 上线管理

| 编号 | 需求 | 优先级 |
|---|---|---|
| REL-01 | 创建上线包：方案版本 + 锁定的模型版本；检查兼容范围和方案版本状态 | P0 |
| REL-02 | 方案包导出和导入（文件），按 H-06 的规则检查 | P0 |
| REL-03 | 上线包文件导出和导入（含目标平台的模型制品） | P1 |
| REL-04 | 基准图集：图像 + 真实判定 + 验收标准 + 一致性标准；冻结与版本 | P1 |
| REL-05 | 验收检查（基准平台），生成基准输出 | P1 |
| REL-06 | 跨平台一致性检查 | P1 |
| REL-07 | 撤回上线包 | P1 |

### 4.5 BC-5 工位运行

| 编号 | 需求 | 优先级 |
|---|---|---|
| STA-01 | 创建工位，绑定图像源；一台电脑可以有多个工位 | P0 |
| STA-02 | 启动、暂停、停止；热启动（恢复上次生效的上线包并预热） | P0 |
| STA-03 | 部署上线包；后台加载；在下一次检测开始前热切换，正在进行的检测不受影响 | P0 |
| STA-04 | 手动回滚；连续 N 次 ERROR 自动回滚 | P0 |
| STA-05 | 部署检查：上线包未撤回、本平台可部署、相机标定有效 | P1 |
| STA-06 | 质量偏离告警（热切换后 NG 率偏离阈值） | P1 |
| STA-07 | 回滚时撤回上线包 | P1 |
| STA-08 | 影子运行 | P2 |

## 5. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-01 | 跨平台 | 核心代码在所有平台上完全相同；平台差异只在适配器中 |
| NFR-02 | 一致性 | 同一个上线包在各平台上的结果满足用户设定的一致性标准 |
| NFR-03 | 性能 | 5MP 图像、约 6 个节点的传统算法流程，在开发机上 < 100 ms；各平台的指标在 POC 后确定 |
| NFR-04 | 不停机 | 热切换不丢失、不中断任何检测；切换本身（不含后台加载）< 1 个检测周期 |
| NFR-05 | 热启动 | 工位从启动到可以检测的时间在 POC 后确定（含模型预热） |
| NFR-06 | 可追溯 | 每次检测可追溯到所用的上线包、方案版本、模型版本、标定档案；每个模型版本可追溯到数据集版本 |
| NFR-07 | 可扩展 | 新增一个算子只需写 1 个类、调用 1 次注册宏；新增一个平台只需实现一组适配器 |
| NFR-08 | 可测试 | 领域层不依赖任何技术，可纯单元测试；上下文边界由构建系统强制 |
| NFR-09 | 离线 | 所有平台可完全离线运行；跨机器传递通过方案包和上线包文件 |
| NFR-10 | 易上手 | 大一学生照着文档，1 天内能完成一个新算子 |

## 6. 范围外

- 模型训练（外部完成）
- 工业相机（GigE Vision / USB3 Vision）、光源控制器
- PLC、IO、MES 对接
- 多机器之间的在线同步、中心服务器
- 用户与权限管理

## 7. 验收方式

- **P0**：完成 [04-poc-plan.md](04-poc-plan.md) 的通过标准；在鸿蒙电脑和 Linux 上跑通“搭方案 → 发布 → 上线包 → 部署 → 检测 → 热切换 → 回滚”。
- **P1**：完成 [ddd/06-scenario-walkthrough.md](ddd/06-scenario-walkthrough.md) 的场景 S1、S2、S3，并有实测数据。
