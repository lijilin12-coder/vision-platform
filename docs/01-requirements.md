## 1. 项目背景与目标

### 1.1 背景

工业外观检测场景多样（缺陷检测、尺寸测量、定位、计数等），每个场景都需要不同的算法组合。本项目做一个**可编排**的视觉检测平台：算法以“算子”为单位，用户通过拖拽连线组合成检测流程（方案），不需要为每个场景写代码。

### 1.2 目标

1. **学习**：覆盖工业视觉的完整技术栈，包括图像处理、测量、深度学习推理、跨端工程。
2. **参赛**：2027 年夏秋参加鸿蒙类比赛，2028 年春参加计算机设计大赛或服务外包大赛。
3. **平台化**：通用场景。节拍和精度由所选算法决定，算法容易定制和扩展。

### 1.3 项目阶段

| 阶段 | 目标 |
|---|---|
| 内部 POC | 验证关键技术假设（见 [04-poc-plan.md](04-poc-plan.md)） |
| MVP | P0 功能完整可用 |
| 参赛版本 | P1 功能完成，具体场景案例打磨完毕 |

## 2. 用户角色

三个角色都必须**同时支持 macOS 和鸿蒙电脑**。

| 角色 | 职责 | Mac | 鸿蒙电脑 |
|---|---|---|---|
| 方案开发者 | 拖拽算子搭流程、画 ROI、调参数、调试中间结果、保存方案 | 浏览器中的 Web 编辑器 | ArkUI 外壳 + ArkWeb 嵌入同一套 Web 编辑器 |
| 操作员 | 选择方案、输入图像（文件或摄像头）、运行、查看 OK/NG 和测量值 | Web 运行页面 | 原生 ArkUI 运行页面 |
| 算子开发者 | 用 C++ 新增算子，注册后在编辑器中直接可用 | Mac 上开发、编译、测试 | 见 F-17、F-18、F-19 |

## 3. 功能需求

优先级：**P0** = POC/MVP 必须有；**P1** = 第一次参赛前完成；**P2** = 加分项。

### 3.1 流程与方案

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-01 | 流程以有向无环图（DAG）表示：节点是算子，边连接有类型的端口；连线时检查类型是否匹配，并禁止形成环 | P0 |
| F-02 | 方案（流程 + 参数 + ROI + 模型引用 + 标定数据）保存为 JSON，带 `schemaVersion`，Mac 和鸿蒙之间可以通用 | P0 |
| F-03 | 运行流程，输出总判定（OK/NG）、各节点的输出和耗时 | P0 |
| F-04 | 调试模式：缓存各节点输出，点击任一节点可以查看中间图像和数据 | P0 |
| F-05 | 运行模式：不缓存中间结果，追求速度 | P1 |
| F-06 | 批量运行：对文件夹中的图像逐张运行，统计良率和各类缺陷数量 | P2 |

### 3.2 图像来源

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-07 | 本地单张图像、文件夹 | P0 |
| F-08 | USB 摄像头：Mac 端；鸿蒙电脑端（依赖 POC-7 的结论） | P1 |

### 3.3 算子库

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-09 | 基础算子：读图、灰度转换、阈值、形态学、Blob 分析、判定 | P0 |
| F-10 | 预处理：滤波、增强、颜色空间转换 | P1 |
| F-11 | 定位与跟随：模板匹配输出位姿，下游 ROI 随位姿移动 | P1 |
| F-12 | 测量：卡尺边缘（亚像素）、直线和圆拟合、距离和角度、像素到毫米标定 | P1 |
| F-13 | 深度学习推理：异常检测（优先）、分类；模型统一用 ONNX 格式输入 | P1 |
| F-14 | 大模型辅助：用自然语言生成流程，或推荐参数 | P2 |

### 3.4 编辑器（Web，两端共用）

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-15 | 节点画布：从算子库拖入节点、连线、删除、撤销；参数面板根据算子的参数定义自动生成 | P0 |
| F-16 | 图像查看器：缩放、平移、像素坐标和灰度值显示；ROI 绘制（矩形、旋转矩形、圆） | P0（查看器）/ P1（ROI） |

### 3.5 算子开发

| 编号 | 需求 | 优先级 |
|---|---|---|
| F-17 | 在 Mac 上开发算子，交叉编译后部署到鸿蒙电脑运行；鸿蒙端提供**算子测试页面**（选择算子、输入测试图、查看输出和耗时） | P0 |
| F-18 | 直接在鸿蒙电脑上用 DevEco Studio 开发、编译算子 | P1 |
| F-19 | 脚本算子：不重新打包 App 就能新增算子（脚本调用 C++ 基础图像函数） | P2 |
| F-20 | 文档《如何新增一个算子》 | P0 |

## 4. 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| N-01 | 平台 | 开发：macOS（Apple Silicon）。运行：macOS、HarmonyOS 7 电脑（设备类型 `2in1`），同时兼容平板（`tablet`） |
| N-02 | 性能 | 在 Mac 上，5MP 图像跑典型传统算法流程（约 6 个节点）< 100 ms；鸿蒙电脑上的指标在 POC 后确定 |
| N-03 | 交互 | 调试时，从点击节点到界面显示中间图像 < 300 ms |
| N-04 | 一致性 | 同一个方案 JSON 在两端运行：传统算法结果一致；推理输出误差 < 1e-3 |
| N-05 | 可扩展 | 新增一个算子只需写 1 个类、调用 1 次注册宏，框架代码和前端代码都不用改 |
| N-06 | 可测试 | vision-core 不依赖任何 UI 和平台；每个算子都有单元测试；有“输入图像 → 期望结果”的回归测试 |
| N-07 | 易上手 | 大一学生照着文档，1 天内能完成一个新算子 |
| N-08 | 离线 | 两端都可以完全离线运行 |

## 5. 范围外（本阶段不做）

- 工业相机（GigE Vision / USB3 Vision）、光源控制器
- PLC、IO 通信，以及与 MES 对接
- 多工位、管理中心、远程下发
- 模型训练平台（训练在平台外用 Python 完成，只交付 ONNX 模型）
- 用户与权限管理
- Windows、Linux 发布包

## 6. 验收方式

- P0：完成 [04-poc-plan.md](04-poc-plan.md) 的全部通过标准，并在两端跑通示例方案“灰度 → 阈值 → Blob → 判定”。
- P1：用一个具体场景（待定，见 [06-open-questions.md](06-open-questions.md)）完成端到端演示，并输出测试数据。
