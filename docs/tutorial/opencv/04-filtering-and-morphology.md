# 第 4 课：滤波与形态学

> 预计用时：2.5 小时
> 示例代码：[`examples/lesson04/`](examples/lesson04/)

## 这一课要回答的问题

第 3 课的示例图像噪声很小，阈值分割出来的结果很干净。真实图像没有这么好：噪声大的时候，分割结果里到处是零碎的小点和小洞。

1. 怎样减小噪声？代价是什么？
2. 均值、高斯、中值三种滤波有什么区别？
3. 分割出来的二值图像不干净，怎样整理？
4. 这些操作会带来什么副作用？

这一课有两类工具，处理的对象不同：

| | 处理什么 | 做什么 |
|---|---|---|
| **滤波** | 灰度图像（分割之前） | 减小噪声 |
| **形态学** | 二值图像（分割之后） | 修整形状：去掉小点、填上小洞 |

## 1. 滤波：用周围的像素算出新的值

### 1.1 问题

一张噪声比较大的图像（`04_noisy.png`，噪声的标准差约 20；第 3 课的图像是 3）。背景 170，零件 70，阈值取 120。背景上的像素要被错分成零件，得偏暗 50 以上，也就是 2.5 倍标准差，概率不高但是像素很多：

```
直接阈值分割：背景那一小块（8000 个像素）里有 53 个被错分成零件
```

打开 `04_noisy_threshold.png`：背景上撒满了白点，零件里撒满了黑点。

### 1.2 均值滤波

办法很直接：**每个像素换成它周围一小块区域的平均值。** 噪声是随机的，有的偏亮有的偏暗，平均之后互相抵消。

```cpp
cv::Mat mean5;
cv::blur(noisy, mean5, cv::Size(5, 5));   // 周围 5×5 = 25 个像素的平均值
```

```
原图：            噪声 20.18，边缘宽度 0
5×5 均值滤波：    噪声 4.12（降到原来的 1/4.9），边缘宽度 4
15×15 均值滤波：  噪声 1.41，边缘宽度 12
```

25 个像素取平均，噪声降到约 1/5。规律是：**N 个像素取平均，噪声降到 1/√N**。滤波之后再做阈值，背景上一个错分的点都没有了（`04_mean_5_threshold.png`）。

**代价是边缘变模糊。** 原图的边缘是“一刀切”的，左边一列是 170，右边一列是 70。滤波之后，边缘附近的像素周围既有背景也有零件，平均出来是中间的灰度，边缘变成了一个 4 个像素宽的过渡带。窗口加大到 15×15，过渡带变成 12 个像素（`04_mean_15.png`，明显糊了）。

这是滤波的基本矛盾：**窗口越大，噪声越小，细节损失越多。** 比窗口小的东西（细的划痕、小的缺陷）会被抹掉。所以窗口只要够用就行，不是越大越好。

### 1.3 自己写一遍

```cpp
cv::Mat mine = noisy.clone();
for (int y = 1; y < noisy.rows - 1; ++y) {
    for (int x = 1; x < noisy.cols - 1; ++x) {
        int sum = 0;
        for (int dy = -1; dy <= 1; ++dy)
            for (int dx = -1; dx <= 1; ++dx) sum += noisy.at<uchar>(y + dy, x + dx);   // 读的是原图
        mine.at<uchar>(y, x) = static_cast<uchar>((sum + 4) / 9);                      // 写到另一张图
    }
}
```

示例检查了它和 `cv::blur(…, cv::Size(3, 3))` 的结果完全相同（最外面一圈除外）。

两个要点：

- **读和写必须是两张不同的图。** 如果边算边写回原图，算下一个像素时用到的邻居已经是被改过的值了，结果是错的。这是一个常见错误。（第 1 课讲过 `cv::Mat b = a;` 不复制像素，所以这里必须 `clone()`。）
- **最外面一圈怎么办？** 图像边上的像素，周围有一部分在图像外面。手写的代码直接跳过了它们；OpenCV 的做法是假想图像在边界处像镜子一样反射出去，用反射出来的值补上。所以结果图像和原图一样大。

这种“每个像素的新值 = 周围像素的加权和”的操作统称**滤波**，那一小块权重叫**核**（kernel）。均值滤波的核是每个位置权重相同。换不同的核，就得到不同的效果：第 6 课找边缘用的也是这个机制，只是核不一样。

### 1.4 高斯滤波

```cpp
cv::GaussianBlur(noisy, gauss, cv::Size(5, 5), 0);
```

均值滤波里 25 个像素的权重一样。**高斯滤波让离中心近的像素权重大、远的权重小**，权重按钟形曲线（高斯函数）分布。

```
5×5 均值滤波：噪声 4.12，边缘宽度 4
5×5 高斯滤波：噪声 5.59，边缘宽度 2
```

同样是 5×5，高斯滤波去噪声稍弱一点，但边缘保持得更好。它更“柔和”，是最常用的一种，很多算法（比如第 6 课的 Canny）第一步就是高斯滤波。

最后一个参数是高斯函数的标准差，决定权重衰减得有多快；写 0 表示让 OpenCV 根据窗口大小自动算。

### 1.5 椒盐噪声和中值滤波

另一种噪声：少数像素完全错了，变成纯黑或纯白，其余像素是好的。相机的坏点、灰尘、传输错误会造成这种情况，叫**椒盐噪声**（`04_salt_pepper.png`）。

均值滤波对它没有办法：

```
椒盐噪声：原来有 595 个坏点；均值滤波后 5121 个像素不对；中值滤波后 0 个
```

一个纯白的坏点（255）参与了周围 9 个像素的平均，把这 9 个像素都拉偏了。坏点没有消失，而是被**抹开**了：不对的像素从 595 个变成了 5121 个（`04_salt_pepper_mean.png`）。

**中值滤波**：每个像素换成周围像素的**中位数**（排序后中间的那个），而不是平均值。

```cpp
cv::medianBlur(peppered, pepperedMedian, 3);   // 周围 3×3 = 9 个像素的中位数
```

9 个像素里有 1 个是 255、8 个是 170 左右。排序之后 255 排在最后，中间的那个是 170 左右。坏点对结果完全没有影响（`04_salt_pepper_median.png`）。

这就是第 14 课（C++ 教程）测量时间时“取中位数而不是平均值”的同一个道理：**中位数不受少数极端值影响。**

中值滤波还有一个好处：**不会让边缘变模糊**。边缘附近的像素，周围要么背景占多数，要么零件占多数，中位数就是占多数的那一方的值，不会出现中间的灰度。示例里中值滤波之后边缘宽度仍然是 0。

它的缺点是比较慢（要排序），并且窗口大的时候会把细线和尖角“吃掉”。

### 1.6 三种滤波怎么选

| | 均值 `blur` | 高斯 `GaussianBlur` | 中值 `medianBlur` |
|---|---|---|---|
| 新的值 | 周围的平均 | 周围的加权平均，近的权重大 | 周围的中位数 |
| 普通噪声（每个像素都有一点） | ✓ | ✓ | 可以，效果稍差 |
| 椒盐噪声（少数像素完全错） | ✗ 抹开 | ✗ 抹开 | ✓ |
| 边缘 | 变模糊 | 变模糊，比均值好 | 保持清晰 |
| 速度 | 最快 | 快 | 较慢 |
| 一般的选择 | 需要很大的窗口时（如估计背景） | **默认用它** | 有坏点、灰尘时 |

**滤波不是必须的。** 如果图像本身噪声很小，或者后面要做精确的边缘测量，就不要滤波，或者只用很小的窗口。滤波永远在损失信息。

## 2. 形态学：整理二值图像

### 2.1 问题

换一个思路：不在分割之前处理，而是分割之后整理结果。对一张噪声很大的零件图像直接做阈值（`04_mask_raw.png`）：

```
直接阈值分割：2563 块白色区域（应该只有 1 块），面积 87716（真实 85903）
```

本来应该是一整块白色的零件，结果有 2563 块：背景上的白色噪声点每个都算一块。零件内部还有很多黑色的小洞。

### 2.2 腐蚀和膨胀

形态学的两个基本操作。它们都用一个小的形状去“扫描”图像，这个小形状叫**结构元素**，最常用的是 3×3 的方块：

```cpp
const cv::Mat k3 = cv::getStructuringElement(cv::MORPH_RECT, cv::Size(3, 3));
cv::erode(square, eroded, k3);
cv::dilate(square, dilated, k3);
```

| 操作 | 规则（对每个像素，看它周围 3×3 的范围） | 效果 |
|---|---|---|
| **腐蚀** `erode` | 只要有一个是黑的，结果就是黑 | 白色区域**缩小**一圈 |
| **膨胀** `dilate` | 只要有一个是白的，结果就是白 | 白色区域**长大**一圈 |

```
100×100 的方块：腐蚀后 9604 个像素（98×98），膨胀后 10404（102×102）
```

用 3×3 的结构元素，四周各缩小或长大 1 个像素；5×5 是 2 个像素，以此类推。

关键在于它们对小东西的影响：

- **腐蚀**：一个 1～2 像素大的白点，缩小一圈之后就**消失**了。
- **膨胀**：一个 1～2 像素大的黑洞，周围的白色长大一圈之后就**被填上**了。

但是单独用它们会改变物体的大小。所以要成对使用。

### 2.3 开运算：去掉小白点

**开运算 = 先腐蚀，再膨胀。**

```cpp
cv::morphologyEx(mask, opened, cv::MORPH_OPEN, k3);
```

- 腐蚀：小白点消失；大的物体缩小一圈。
- 膨胀：大的物体长回原来的大小；已经消失的小白点**不会再回来**（什么都没有，无从长起）。

```
开运算之后：1 块白色区域
```

2563 块变成 1 块（`04_mask_opened.png`）。

### 2.4 闭运算：填上小黑洞

**闭运算 = 先膨胀，再腐蚀。** 正好反过来。

```cpp
cv::morphologyEx(opened, cleaned, cv::MORPH_CLOSE, k3);
```

- 膨胀：小黑洞被填上；物体长大一圈。
- 腐蚀：物体缩回原来的大小；已经填上的洞不会再出现。

```
零件内部一块 8400 个像素的区域里：闭运算前有 94 个黑点，之后 0 个
整理之后：1 块，面积 85850，和真实面积相差 0.06%
```

零件上的两个大圆孔还在：闭运算只填**比结构元素小**的洞（`04_mask_cleaned.png`）。

记忆方法：**开**运算把细小的连接断**开**、去掉小白点；**闭**运算把小的缝隙**闭**合、填上小黑洞。

### 2.5 结构元素的大小决定“多小算小”

一张图里有三个形状：100×100 的大方块、3 像素宽的细线、7×7 的小点（`04_shapes.png`）。

```
三个形状：5×5 开运算后剩 2 个，9×9 开运算后剩 1 个
```

- 5×5 开运算：细线只有 3 像素宽，里面放不下 5×5 的方块，被去掉。7×7 的小点放得下，留下。
- 9×9 开运算：小点也放不下 9×9，被去掉。只剩大方块，而且大小完全没变（仍然是 10000 个像素）。

规则：**开运算去掉所有“放不下结构元素”的白色部分。** 所以结构元素的大小要按“想去掉多大的东西、想保留多大的东西”来选，介于两者之间。

反过来用，这是一个找细小东西的办法：

```cpp
cv::Mat thinParts = shapes - open5;   // 原图 − 开运算的结果 = 被去掉的细小部分
```

得到的正好是那条细线（`04_shapes_thin_parts.png`）。找划痕、毛刺、细的裂纹时会用到这个思路。

### 2.6 副作用

**闭运算会把靠得近的物体连起来。**

```
相隔 6 个像素的两个方块，9×9 闭运算后连成了一个
```

两个零件之间的缝隙，对闭运算来说就是一个“小黑洞”。如果任务是数个数，这就数错了（`04_two_closed.png`）。

同样，开运算会把细的连接断开：一个物体如果中间有一段很细，开运算之后可能变成两个。

所以结构元素的大小是有上限的：**闭运算的结构元素要小于物体之间的最小间距；开运算的结构元素要小于物体上最细的部分。**

### 2.7 其他

```cpp
cv::morphologyEx(cleaned, outline, cv::MORPH_GRADIENT, k3);   // 膨胀 − 腐蚀 = 边界上的一圈
```

膨胀的结果减去腐蚀的结果，只剩下物体边界上的一圈，是得到轮廓的一个简单办法（`04_outline.png`）。

结构元素除了方形（`MORPH_RECT`），还有椭圆（`MORPH_ELLIPSE`）和十字（`MORPH_CROSS`）。方形最快；椭圆在各个方向上更均匀，不会把圆角处理成方角。

## 3. 滤波还是形态学？

两种办法都能得到干净的分割结果。怎么选？

| | 先滤波，再阈值 | 先阈值，再形态学 |
|---|---|---|
| 作用在 | 灰度值上 | 形状上 |
| 适合 | 噪声是主要问题；后面还要用灰度图 | 知道“目标至少多大、间距至少多少” |
| 对边界位置的影响 | 边缘模糊，但位置基本不偏 | 开、闭成对使用时基本不变 |
| 常见组合 | 轻微的高斯滤波 → 阈值 → 小的开运算和闭运算 | |

实际中经常两者都用一点：先用小窗口的滤波把噪声压一压，分割之后再用小的开、闭运算收拾剩下的零碎。**每一步都用尽量小的窗口。**

和第 3 课一样的提醒：噪声大，首先应该检查的是光照够不够亮、相机的增益是不是开得太高、曝光时间是不是太短。图像本身拍好了，这些步骤就可以很轻，甚至不需要。

## 4. 和平台的关系

平台现在还没有滤波和形态学算子（现有的是图像输入、灰度、阈值、Blob、计数判定、反色）。这两类是最基本的预处理算子，是很合适的入门任务：每个算子只有一两个参数，输入输出的类型也简单。

| 可以新增的算子 | 输入 → 输出 | 参数 |
|---|---|---|
| 高斯滤波 | 图像 → 图像 | 窗口大小 |
| 中值滤波 | 图像 → 图像 | 窗口大小 |
| 开运算、闭运算 | 区域 → 区域 | 结构元素的大小和形状 |

注意形态学算子的输入输出是**区域**（`Region`，阈值算子的输出），不是图像。这是平台用类型区分“灰度图像”和“分割结果”带来的好处：方案编辑的时候，形态学算子接不到灰度图像上，接错了当场就会报错。

## 6. 练习

1. **边算边写的错误**：把第 1.3 节手写的均值滤波改成直接写回 `noisy`（不用另一张图），和正确结果用 `absdiff` 比较。差别大吗？差别集中在哪里？
2. **手写中值滤波**：自己实现 3×3 的中值滤波（把 9 个值放进数组，用 `std::nth_element` 找中位数），和 `cv::medianBlur` 的结果比较。
3. **噪声和窗口的关系**：用 3×3、5×5、7×7、9×9 的均值滤波，分别量出噪声。画一张表，验证“降到 1/√N”。
4. **手写腐蚀**：自己实现 3×3 的腐蚀，和 `cv::erode` 的结果比较。然后想一想：腐蚀其实就是“取周围 9 个像素的最小值”，膨胀是“取最大值”。这和中值滤波是什么关系？
5. **顺序重要吗**：对 `04_mask_raw.png`，先闭后开，和先开后闭，结果一样吗？各有多少块白色区域？为什么这张图应该先开后闭？
6. **把不均匀的光照除掉**（第 3 课留下的问题）：对 `cvtut::applyShading(cvtut::makePartImage(), 1.0, 0.35)` 这张图，用一个很大的窗口（如 151×151）做均值滤波，得到对“光照分布”的估计；把原图转成浮点数（第 2 课），除以这个估计，再乘以一个常数转回 8 位。然后用大津法分割。结果比第 3 课好了吗？哪里还有问题？为什么？（提示：大零件本身也被当成了“光照”的一部分。更可靠的做法是事先拍一张没有零件的空白图像作为光照分布，这叫**平场校正**。）
7. **找细线**：第 1 课的零件上有一道亮的划痕。用“原图 − 开运算”的思路把它找出来。先想清楚：应该对什么做阈值？结构元素取多大？
8. **给平台加算子**：按第 4 节的表格，实现“高斯滤波”算子并写测试。参考 [如何新增一个算子](../../dev/how-to-add-operator.md)。窗口大小必须是奇数，参数不合法时应该怎样报告？
