## 1. 彩色图像：一个像素三个数

灰度图的一个像素是一个数。彩色图的一个像素是**三个数**，分别表示红、绿、蓝三种光的强度，各自 0～255。这三个数叫三个**通道**。

在 OpenCV 里，三个通道的顺序是 **蓝、绿、红（BGR）**，而不是通常说的 RGB。

```cpp
cv::Mat red(100, 100, CV_8UC3, cv::Scalar(0, 0, 255));   // 蓝 0，绿 0，红 255：纯红色

cv::Vec3b pixel = red.at<cv::Vec3b>(0, 0);   // Vec3b：3 个 uchar
pixel[0]   // 0    蓝
pixel[1]   // 0    绿
pixel[2]   // 255  红
```

- 类型是 `CV_8UC3`：8 位、无符号、3 个通道。
- 用 `at` 访问时类型是 `cv::Vec3b`。
- 在内存里三个数挨着放：`B G R B G R B G R ...`，一个像素 3 字节，640 像素宽的图像一行是 1920 字节。

> BGR 是历史原因：OpenCV 诞生时，当时常见的相机和 Windows 的位图格式用的是这个顺序。
>
> 这个顺序是实际工作中的常见错误来源：别的库（界面、深度学习框架、网页）几乎都用 RGB。图像从 OpenCV 交给它们时如果忘了转换，红色和蓝色就会对调。示例里的 `02_swapped_wrong_colors.png` 就是这种错误的样子。

## 2. 拆开来看

```cpp
std::vector<cv::Mat> bgr;
cv::split(board, bgr);      // bgr[0] 蓝，bgr[1] 绿，bgr[2] 红，每个都是单通道图像
cv::merge(bgr, merged);     // 合并回去
```

示例图像是一块电路板（`02_board.png`）：绿色的板子，上面有红色元件、蓝色芯片、黄色电容。

运行之后打开 `02_channel_red.png`、`02_channel_green.png`、`02_channel_blue.png` 对照看。每一张都是灰度图，表示那种颜色的光有多强：

| 物体 | 在红通道里 | 在绿通道里 | 在蓝通道里 |
|---|---|---|---|
| 红色元件 | **亮**（206） | 暗（29） | 暗（25） |
| 蓝色芯片 | 暗 | 暗 | **亮** |
| 黄色电容 | **亮** | **亮** | 暗 |
| 绿色板子 | 暗 | 较亮 | 暗 |

黄色在红、绿两个通道里都亮：黄光 = 红光 + 绿光。

这张表有一个很实用的结论：**想把某个东西和背景分开，可以挑它们差别最大的那个通道**。要找红色元件，红通道里它是亮的、板子是暗的，对比最强。很多时候只取一个通道，比转成灰度效果更好。

## 3. 彩色转灰度

```cpp
cv::Mat gray;
cv::cvtColor(board, gray, cv::COLOR_BGR2GRAY);
```

灰度值不是三个通道的简单平均，而是加权平均：

```
灰度 = 0.299 × 红 + 0.587 × 绿 + 0.114 × 蓝
```

示例里取了红色元件上的一个像素来验证：OpenCV 算出 81，按公式算出 81.47，而简单平均是 86.67。

权重不一样，是因为人眼对绿光最敏感、对蓝光最不敏感。这个公式是为了让灰度图“看起来”和彩色图一样亮。

**为什么工业检测大多用灰度图？**

- 很多工业相机本身就是黑白的：同样的价格，黑白相机分辨率更高、对光更敏感。
- 数据量是彩色的三分之一，处理更快。
- 尺寸测量、划痕、缺口这些任务只需要亮度的差别。

需要彩色的情况：检查颜色本身（线序、色环、有没有装错颜色的零件）。

转灰度的代价是丢失信息。打开 `02_gray.png`：红色元件（灰度约 81）和绿色板子差得不多，在灰度图里几乎分不出来，而在红通道里它们一个亮一个暗。**转灰度之前，先想一想要找的东西在灰度图里还看不看得出来。**

> **和平台的关系**：平台的 `to_gray` 算子（[`operators/src/to_gray.cpp`](../../../operators/src/to_gray.cpp)）做的就是这一步。读完这一节，你可以想一想它还缺什么：只能按固定公式转灰度，不能选择单个通道。这是一个很好的练习题（见练习 6）。

## 4. 按颜色找东西：HSV

要找出图像里的黄色电容。用 BGR 来描述“黄色”很别扭：红和绿都大、蓝小，但是到底多大算大？而且光线一暗，三个数一起变小。

换一种表示颜色的方式，**HSV**：

| 分量 | 含义 | OpenCV 里 8 位图像的范围 |
|---|---|---|
| H（色相） | 是什么颜色：红、黄、绿、青、蓝、紫，排成一个圆环 | 0～179 |
| S（饱和度） | 颜色有多纯：0 是灰色，越大越鲜艳 | 0～255 |
| V（亮度） | 有多亮 | 0～255 |

好处是“什么颜色”和“有多亮”被分开了。光线变暗，主要是 V 变小，H 基本不变。

```cpp
cv::Mat hsv;
cv::cvtColor(board, hsv, cv::COLOR_BGR2HSV);

// 黄色：H 在 20～35 之间，并且足够鲜艳、足够亮
cv::Mat yellowMask;
cv::inRange(hsv, cv::Scalar(20, 100, 100), cv::Scalar(35, 255, 255), yellowMask);
```

`inRange` 的结果是一张**掩膜**（mask）：单通道图像，三个分量都落在范围内的像素是 255，其余是 0。打开 `02_mask_yellow.png`，是黑底上两个白色的圆。

因为示例图像是自己画的，可以检查结果对不对：

```
黄色像素 5642 个；两个半径 30 的圆的面积约 5654.86
```

相差 0.2%。

三处容易出错的地方：

**① H 的范围是 0～179，不是 0～360。** 色相本来是角度（0～360 度），但 8 位放不下 360，OpenCV 把它除以了 2。从别处查到的色相值要先除以 2。

**② 红色跨在圆环的接头上。** 色相是一个环，红色正好在 0 的两侧（0～10 和 170～179）。找红色要分两段，再合并：

```cpp
cv::inRange(hsv, cv::Scalar(0, 100, 100), cv::Scalar(10, 255, 255), redLow);
cv::inRange(hsv, cv::Scalar(170, 100, 100), cv::Scalar(179, 255, 255), redHigh);
cv::bitwise_or(redLow, redHigh, redMask);
```

示例图像带噪声，红色元件的色相有的像素略大于 0，有的略小于 0（也就是 179 附近）。只找一段，就会漏掉一部分像素。

**③ 颜色很淡或者很暗时，色相没有意义。** 灰色、白色、黑色没有“是什么颜色”可言，这些像素算出来的 H 是随机的。所以范围里一定要同时限制 S 和 V 的下限（上面的两个 100）。

掩膜的常见用法：

```cpp
cv::countNonZero(yellowMask);            // 数一数有多少像素
board.copyTo(onlyYellow, yellowMask);    // 只复制掩膜里不为 0 的位置（02_only_yellow.png）
```

## 5. 像素的数据类型

### 5.1 200 + 100 = ?

8 位像素只能表示 0～255。

```cpp
const uchar a = 200, b = 100;
uchar wrapped   = static_cast<uchar>(a + b);          // 44
uchar saturated = cv::saturate_cast<uchar>(a + b);    // 255
```

- 直接转换：300 放不进 8 位，只留下低 8 位，300 − 256 = **44**。很亮加很亮，结果很暗。这叫**回绕**。
- `cv::saturate_cast`：超过 255 取 255，低于 0 取 0。这叫**饱和**。对图像来说这才是合理的：已经最亮了，再加还是最亮。

打开 `02_brighter_wrong.png` 看回绕的后果：想把整张图调亮 100，结果原来亮的背景（171）变成了几乎全黑（15），而原来暗的零件倒是变亮了。

OpenCV 自己的运算都带饱和处理：

```cpp
const cv::Mat right = part + 100;        // 背景：171 + 100 → 255
```

**规则：自己写循环处理像素时，凡是结果可能超出范围的，都要用 `cv::saturate_cast`。** 更好的做法是用 OpenCV 的运算。

### 5.2 减法也会饱和

```cpp
const cv::Mat darker = part - 30;
const cv::Mat minus = darker - part;     // 每个像素都是 −30 → 全部变成 0
cv::absdiff(darker, part, diff);         // 差的绝对值：30
```

两张图相减，暗的减亮的全是 0，看起来像是“没有差别”。比较两张图像要用 **`cv::absdiff`**。这是缺陷检测里“和标准图像比较”的基本操作，用减号是一个很隐蔽的错误：只能发现一个方向的差别（变亮的），另一个方向的（变暗的）悄悄丢了。

### 5.3 需要小数或负数时：转成浮点数

8 位整数不能表示小数和负数。计算的中间结果如果有小数或负数，先转成浮点数，算完再转回来。

```cpp
cv::Mat asFloat;
part.convertTo(asFloat, CV_32F, 1.0 / 255.0);         // 转成 32 位浮点数，同时乘以 1/255：范围变成 0～1

cv::Mat contrast = (asFloat - 0.5f) * 1.5f + 0.5f;    // 以中间灰度为中心，把对比度拉大 1.5 倍

cv::Mat contrast8;
contrast.convertTo(contrast8, CV_8U, 255.0);          // 乘以 255 转回 8 位，自动四舍五入并饱和
```

`convertTo(输出, 类型, 乘数, 加数)`：改变**数据类型**，可以顺便做一次乘和加。

注意它和 `cvtColor` 的区别：`convertTo` 改变每个数的类型（8 位整数 → 浮点数），不改变通道数；`cvtColor` 改变颜色的表示方式（BGR → 灰度），通常会改变通道数。

常用的类型：

| 类型 | 每个数 | 范围 | 用途 |
|---|---|---|---|
| `CV_8U` | 8 位无符号整数 `uchar` | 0～255 | 普通图像 |
| `CV_16U` | 16 位无符号整数 `ushort` | 0～65535 | 10 位、12 位的工业相机；深度图 |
| `CV_16S` | 16 位有符号整数 `short` | −32768～32767 | 有正有负的中间结果（如第 6 课的梯度） |
| `CV_32F` | 32 位浮点数 `float` | 小数 | 需要小数的计算；模板匹配的结果（第 8 课） |

后面加 `C1`、`C3` 表示通道数，如 `CV_32FC1`。

### 5.4 at 的类型必须和图像一致

```cpp
asFloat.at<float>(y, x)    // 正确：CV_32F 对应 float
asFloat.at<uchar>(y, x)    // 能编译，能运行，但读到的是浮点数四个字节里的某一个
```

第二种写法不会报错，只会得到莫名其妙的数。这是 OpenCV 里最难查的一类错误，因为代码看起来完全正常。

| 图像类型 | `at` 的类型 |
|---|---|
| `CV_8UC1` | `uchar` |
| `CV_8UC3` | `cv::Vec3b` |
| `CV_16UC1` | `ushort` |
| `CV_16SC1` | `short` |
| `CV_32FC1` | `float` |

拿不准时，先用 `image.type() == CV_8UC1` 这样的判断检查一下。写算子时，在入口处检查输入图像的格式是一个好习惯。

### 5.5 16 位图像

有些工业相机每个像素输出 10 位或 12 位（0～1023 或 0～4095），能分辨更细的亮度差别。这样的图像用 `CV_16U` 存放。

```cpp
cvtut::save(out / "02_part_16bit.png", image16);                           // PNG 支持 16 位
cvtut::load(out / "02_part_16bit.png", cv::IMREAD_UNCHANGED).type();       // CV_16UC1
cvtut::load(out / "02_part_16bit.png", cv::IMREAD_GRAYSCALE).type();       // CV_8UC1：被悄悄转成了 8 位
```

这是第 1 课“读图时写明读取方式”的另一个理由：用 `IMREAD_GRAYSCALE` 或默认方式读 16 位图像，多出来的精度会被直接丢掉，没有任何提示。

用图片查看器打开 `02_part_16bit.png` 会发现它很暗。这是正常的：数据只用到了 0～4095，而 16 位的最大值是 65535，查看器按 65535 是白色来显示。

> **和平台的关系**：平台的 `Image` 目前只支持 8 位的灰度和彩色两种格式（`Gray8`、`Bgr8`）。接入 12 位相机时需要扩展。
