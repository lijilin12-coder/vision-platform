# 第 5 课：Blob 分析

> 预计用时：2.5 小时
> 示例代码：[`examples/lesson05/`](examples/lesson05/)

## 这一课要回答的问题

前两课得到了一张干净的二值图像：白的是目标，黑的是背景。但它还只是一堆像素，回答不了“有几个”“每个多大”“在哪里”“朝哪个方向”。

1. 怎样把白色的像素归成一个一个的物体？
2. 每个物体可以量出哪些特征？
3. 怎样用这些特征把想要的物体挑出来？
4. 怎样知道一个物体的方向？
5. 这种方法什么时候不好用？

**Blob**（英文原意是“一团”）指二值图像里连成一片的白色区域。**Blob 分析**就是找出每一团，量出它的特征。这是工业视觉里用得最多的一类方法：数数量、测面积、定位、找缺陷，大部分都可以归结成“分割 → Blob 分析 → 按特征判断”。

## 1. 连通区域

### 1.1 找出每一块

```cpp
cv::Mat labels, stats, centroids;
const int n = cv::connectedComponentsWithStats(mask, labels, stats, centroids, 8);
```

示例图像是第 3 课的 24 个圆点。函数返回 `n = 25`：**第 0 个是背景**，所以有 24 块。遍历时从 1 开始，这是一个容易错的地方。

三个输出：

| 输出 | 内容 |
|---|---|
| `labels` | 和原图一样大的图像，每个像素的值是“它属于第几块”，背景是 0。类型是 `CV_32SC1`（每个像素是一个 `int`），用 `at<int>` 读 |
| `stats` | 每一块一行，5 个数：外接框的左、上、宽、高，以及面积（像素个数） |
| `centroids` | 每一块一行，2 个数：重心的 x、y。类型是 `double` |

```cpp
const int area = stats.at<int>(i, cv::CC_STAT_AREA);
const int left = stats.at<int>(i, cv::CC_STAT_LEFT);     // 还有 CC_STAT_TOP、CC_STAT_WIDTH、CC_STAT_HEIGHT
const double cx = centroids.at<double>(i, 0);
const double cy = centroids.at<double>(i, 1);
```

第一个圆点的结果：

```
面积 197（半径 8 的圆约 201），外接框 左 87 上 97 宽 17 高 17，重心 (95, 105)
```

和画图时的参数（圆心 (95, 105)，半径 8）一致。

### 1.2 这是你熟悉的算法

连通区域就是竞赛里的“数连通块”：在网格上做 BFS、DFS 或者并查集。C++ 教程第 00 课的例子 `blob_count` 做的正是这件事。OpenCV 的实现用的是更快的扫描算法，但结果相同。

你已经会写它了。这里要学的是它在视觉里怎么用。

### 1.3 重心：比一个像素更精确

**重心**是这一块所有像素的坐标的平均值。

```
24 个重心离理想网格位置最远 0 个像素
```

注意重心是小数。一个圆点有约 200 个像素，200 个坐标取平均，边界上个别像素的对错对平均值影响很小。所以**重心的定位精度可以远小于 1 个像素**，这叫**亚像素精度**。

（这里的 0 是因为示例图像噪声很小、圆点画在整数坐标上。真实图像不会正好是 0，但达到 0.1 个像素左右是常见的。）

这是一个重要的认识：图像的分辨率是 1 个像素，不代表测量精度只能到 1 个像素。很多像素一起参与计算，精度可以高得多。相机标定用的标定板上印的是圆点，原因就在这里。

### 1.4 4 邻域和 8 邻域

“连着”有两种定义：

```
4 邻域：只看上下左右          8 邻域：斜着的也算

      ·  █  ·                     █  █  █
      █  ●  █                     █  ●  █
      ·  █  ·                     █  █  █
```

两个只在一个角上相碰的方块（`05_corner_touch.png`）：

```
8 邻域算 1 块，4 邻域算 2 块
```

一般用 8 邻域（最后一个参数写 8），平台的 Blob 算子也是。只需要记住有这个区别：斜着的细线在 4 邻域下会碎成很多块。

### 1.5 按面积筛选

第 4 课用开运算去掉噪声造成的小白点。还有一个更直接的办法：先不管它们，找出所有的块之后，**只留下面积合适的**。

```cpp
for (int i = 1; i <= total; ++i) {
    const int a = stats.at<int>(i, cv::CC_STAT_AREA);
    if (a >= 100 && a <= 400) ++kept;   // 圆点的面积约 200
}
```

```
噪声很大的图像：共 871 块，面积在 100～400 之间的有 24 块
```

871 块里只有 24 块是真正的圆点，按面积一筛就干净了。

和开运算相比，面积筛选不会改变物体的形状，而且条件的含义很清楚（“面积小于 100 的不要”）。平台的 Blob 算子的两个参数 `minArea`、`maxArea` 就是这个作用。

面积的上限同样有用：下限去掉噪声，上限去掉“一大片”的异常（比如第 3 课里光照不均匀造成的整片白色）。

## 2. 轮廓

连通区域给出的是“哪些像素属于这一块”。另一种表示方法是**轮廓**：这一块的边界上的点，按顺序排成一圈。

```cpp
std::vector<std::vector<cv::Point>> contours;
cv::findContours(mask, contours, cv::RETR_EXTERNAL, cv::CHAIN_APPROX_SIMPLE);
```

`contours` 是一个 `vector` 的 `vector`：每条轮廓是一串点，所有轮廓放在一起。

### 2.1 两个参数

**第三个参数：要哪些轮廓。**

| 写法 | 含义 |
|---|---|
| `cv::RETR_EXTERNAL` | 只要最外面的轮廓，不管里面的孔 |
| `cv::RETR_CCOMP` | 外轮廓和孔都要，并告诉你哪个是孔 |

示例里对带两个圆孔的零件：

```
RETR_EXTERNAL 找到 1 条轮廓；RETR_CCOMP 找到 4 条，其中 3 条是孔
```

3 个孔：两个圆孔，还有那道划痕（它比阈值亮，在零件的掩膜里是一条黑色的缝）。“零件上应该有几个孔”本身就是一项检测内容：多了一个，说明有不该有的东西。

**第四个参数：保留多少个点。**

| 写法 | 含义 |
|---|---|
| `cv::CHAIN_APPROX_NONE` | 边界上的每一个点都保留 |
| `cv::CHAIN_APPROX_SIMPLE` | 水平、竖直、斜 45 度的直线段只保留两端 |

一个正放的矩形用 `CHAIN_APPROX_SIMPLE` 只有 4 个点。要计算周长、圆度时两种都可以；要对轮廓上的每个点做计算时用 `CHAIN_APPROX_NONE`。

### 2.2 轮廓面积不等于像素个数

```
200×100 的矩形：像素个数 20000，轮廓面积 19701，周长 596
```

`cv::contourArea` 算出来是 199 × 99 = 19701，比像素个数少。原因是轮廓上的点位于**边界像素的中心**，这些点围成的多边形，四周各比实际的区域小半个像素。

两种面积都是“对的”，只是定义不同。重要的是**在一个项目里始终用同一种**，尤其是面积的阈值不能一会儿按这种算、一会儿按那种算。小的物体上两者相差的比例很大：一个 3×3 的小点，像素个数是 9，轮廓面积是 4。

## 3. 形状特征

有了轮廓，可以算出很多描述形状的数。示例图像里有 6 个形状：两个圆、一个正方形、两根长条、一个矩形（`05_scene.png`）。

### 3.1 最小外接矩形

`stats` 里的外接框是正放的。物体斜着的时候，正放的外接框很大，说明不了物体本身的尺寸。

```cpp
const cv::RotatedRect box = cv::minAreaRect(contour);   // 面积最小的外接矩形，可以是斜的
box.center        // 中心
box.size          // 两条边的长度
```

它的两条边长就是物体的“长”和“宽”（哪个是 `width` 哪个是 `height` 不固定，自己取大的和小的）。

### 3.2 长宽比和圆度

```cpp
const double aspect = longSide / shortSide;                              // 长宽比
const double round = 4 * kPi * area / (perimeter * perimeter);           // 圆度
```

**圆度** = 4π × 面积 ÷ 周长²。同样的面积，圆的周长最短，所以圆的圆度最大（理论上是 1），形状越不规则、越细长，圆度越小。

```
  中心 (100, 100)  面积 4912  圆度 0.887  长宽比 1        ← 圆
  中心 (520, 380)  面积 4912  圆度 0.887  长宽比 1        ← 圆
  中心 (300, 100)  面积 6241  圆度 0.785  长宽比 1        ← 正方形
  中心 (330, 300)  面积 7240  圆度 0.605  长宽比 1.98     ← 矩形
  中心 (480, 120)  面积 6292  圆度 0.434  长宽比 3.98     ← 长条
  中心 (140, 340)  面积 6461  圆度 0.476  长宽比 3.89     ← 长条
```

- 圆度大于 0.85 的有 2 个，正好是两个圆。
- 长宽比大于 3 的有 2 个，正好是两根长条。
- 正方形的长宽比也是 1，只看长宽比分不开圆和正方形；圆度可以（0.887 和 0.785）。

注意**圆的圆度是 0.887，不是 1**。像素画出来的圆，边界是锯齿状的，周长比真正的圆长，圆度就小于 1。而正方形的 0.785 正好是理论值 π/4。所以判断“是不是圆”的门限不能照着理论值定，要拿实际的图像量一下再定。这是通用的做法：**门限来自实际数据，不来自公式。**

打开 `05_scene_marked.png`：圆上画了红点，长条画了绿框。

### 3.3 常用特征一览

| 特征 | 怎么算 | 用来区分什么 |
|---|---|---|
| 面积 | 像素个数，或 `contourArea` | 大小；去掉噪声 |
| 外接框的宽、高 | `stats` 或 `boundingRect` | 大致尺寸 |
| 长、宽 | `minAreaRect` 的两条边 | 物体本身的尺寸，不受摆放角度影响 |
| 长宽比 | 长 ÷ 宽 | 细长的（划痕、引脚）和团状的（点、孔） |
| 圆度 | 4π × 面积 ÷ 周长² | 圆的和不圆的 |
| 孔的个数 | `RETR_CCOMP` | 有没有多出来或少了的孔 |
| 重心 | `centroids` 或矩 | 位置 |
| 方向 | 下一节 | 朝向 |

缺陷检测里经常是几个特征一起用：比如“面积大于 20 且长宽比大于 5”是划痕，“面积大于 50 且圆度大于 0.7”是凹坑。

## 4. 方向

零件每次放上来的角度不一样。怎样知道它转了多少度？

### 4.1 先约定角度的方向

图像的 y 轴朝下（第 1 课），所以角度的正方向也和数学课上相反：**在屏幕上看，角度增大是顺时针转**。示例里“转了 30 度”的长条，是右端朝下倾斜的（看 `05_scene.png` 右上角那一根）。

角度的约定是这一类代码里最容易出错的地方：正方向是顺时针还是逆时针、单位是度还是弧度、范围是 0～180 还是 −90～90。**每次用到角度，都先用一个已知角度的图形验证一下。** 示例就是这么做的。

### 4.2 两种算法

**办法一：最小外接矩形的长边方向。**

```cpp
cv::Point2f p[4];
cv::minAreaRect(contour).points(p);                    // 四个角
// 取长的那条边，用 atan2 算它和 x 轴的夹角
```

`cv::RotatedRect` 自己也有一个 `angle` 成员，但它的含义在 OpenCV 的不同版本里变过，而且不保证对应的是长边。示例里没有用它，而是自己从四个角算，这样含义是确定的。

**办法二：用“矩”。**

```cpp
const cv::Moments m = cv::moments(contour);
const double angle = 0.5 * std::atan2(2 * m.mu11, m.mu20 - m.mu02) * 180 / kPi;
```

**矩**是对所有像素坐标的统计。`mu20` 表示像素在 x 方向上分布得有多散，`mu02` 是 y 方向，`mu11` 表示 x 和 y 是不是一起变化（物体是不是斜的）。这个公式算出的是“像素分布得最长的那个方向”。公式的推导需要线性代数，现在只需要会用。

结果：

```
  长条（30 度）： 用矩算出 30.09 度，用最小外接矩形算出 30.10 度
  长条（-50 度）：用矩算出 -49.81 度，用最小外接矩形算出 -49.84 度
  矩形（75 度）： 用矩算出 74.58 度，用最小外接矩形算出 74.58 度
```

两种方法的误差都在 0.5 度以内。

| | 最小外接矩形 | 矩 |
|---|---|---|
| 依据 | 只看最外面的几个点 | 所有像素都参与 |
| 边界上有毛刺、缺口时 | 受影响大 | 受影响小 |
| 适合 | 轮廓干净的矩形物体 | 一般情况 |

### 4.3 两个根本的局限

**① 分不出头和尾。**

```
长条转 30 度和转 210 度：两张图有 0 个像素不同
```

一根长条转 180 度之后和原来一模一样，所以算出来的方向只能在 180 度的范围内。如果零件有头尾之分（比如一端有缺口的芯片），从方向上看不出它是不是放反了。

**② 对称的形状没有方向。**

```
正方形：mu20 = 3.24584e+06，mu02 = 3.24584e+06，mu11 = 0
```

正方形在 x 和 y 两个方向上“一样长”，公式变成了 `atan2(0, 0)`，结果没有意义。圆也是这样。实际图像里因为噪声，`mu20` 和 `mu02` 不会正好相等，公式会给出一个数，但那个数是噪声决定的，每次都不一样。

也就是说，用 Blob 的方向来定位，**只适用于细长的、形状简单的物体**，而且只能定到 180 度以内。接近方形或圆形的零件、需要区分头尾的零件，要靠零件上的细节来确定角度。这就是后面第 8 课模板匹配和大作业要解决的问题。

## 5. Blob 分析的局限

**挨在一起的物体会被当成一个。**

```
两个有一点重叠的圆：找到 1 块，面积 5568（一个圆约 2827），重心 x = 117.5
```

两个圆只要有一个像素相连，就是一块（`05_touching.png`）。数量错了，面积是两个的和，重心落在两个圆的中间，那里哪个圆的圆心都不是。

可以从面积看出异常（约是一个圆的 2 倍），但要把它们分开需要别的方法。产线上的做法通常是从源头避免：让零件分开摆放。

**完全依赖分割的质量。** Blob 分析的输入是二值图像。分割错了，后面全错：阈值偏了一点，面积就变了；光照不均匀让物体缺了一块，形状特征就都不对了。Blob 分析自己发现不了这些问题。

**用不上灰度信息。** 二值化之后，物体内部的图案、纹理都丢掉了。两个轮廓相同但表面印字不同的零件，Blob 分析分不出来。

适合用 Blob 分析的情况：**目标和背景对比明显、物体互相分开、要回答的问题和形状大小有关。** 这在工业现场很常见，因为光照和摆放都是可以设计的。

## 6. 和平台的关系

打开 [`operators/src/blob.cpp`](../../../operators/src/blob.cpp)，它的核心就是第 1 节的代码：

```cpp
const int n = cv::connectedComponentsWithStats(imaging::view(in.value().mask()), labels, stats, centroids, 8);

for (int i = 1; i < n; ++i) {  // 0 是背景
    const double area = stats.at<int>(i, cv::CC_STAT_AREA);
    if (area < minArea || area > maxArea) continue;
    // ... 把面积、重心、外接框填进 Blob
}
```

- 输入是 `Region`（阈值算子的输出），输出是 `BlobList`（一个 `std::vector<Blob>`）和个数。
- `Blob` 结构体（[`geometry.h`](../../../core/kernel/include/vision/kernel/geometry.h)）目前有面积、重心、外接框，**没有**长宽、圆度、方向。
- 后面的 `judge_count` 算子根据个数给出合格或不合格。

现有的方案“灰度 → 阈值 → Blob → 计数判定”，就是这三课内容连起来：第 2 课、第 3 课、第 5 课。

这一课学到的特征，平台都还没有，是很实在的扩展方向：给 `Blob` 增加圆度、长宽比、方向，再增加一个“按特征筛选”的算子。注意 `Blob` 在共享内核里，改它会影响所有用到它的地方，动手之前先和架构负责人商量。

## 8. 练习

1. **自己数连通块**：用 BFS 或并查集自己实现连通区域标记（8 邻域），输出每一块的面积和重心，和 `connectedComponentsWithStats` 的结果比较。
2. **重心的精度**：把圆点的圆心画在非整数位置上（提示：`cv::circle` 的最后一个参数 `shift` 可以表示小数坐标；或者画一张 4 倍大的图再缩小），加上不同大小的噪声，量一量重心的误差。噪声多大时误差超过 0.5 个像素？
3. **数孔**：写一个函数，输入零件的掩膜，返回孔的个数和每个孔的面积。用它检查“零件上应该正好有两个圆孔，每个面积在 3500～4200 之间”。带划痕的零件应该判为不合格。
4. **分类**：对 `05_scene.png` 里的 6 个形状，写一个函数把每个形状判断为“圆”“正方形”“矩形”“长条”之一。只用圆度和长宽比够吗？
5. **角度约定**：`cv::RotatedRect` 有一个 `angle` 成员。对示例里的三个旋转矩形，把 `minAreaRect(contour).angle` 和 `size.width`、`size.height` 打印出来。它和画图时的角度是什么关系？什么时候 `width` 是长边，什么时候是短边？（这个练习的目的是让你亲眼看到为什么示例里不直接用它。）
6. **区分头尾**（思考并实现）：一根长条的一端被切掉了一个角。它的方向用矩可以算出来（差 180 度不确定）。怎样进一步判断缺角的一端朝哪边？（提示：重心和最小外接矩形的中心不重合了。）
7. **分开粘连的圆**（进阶）：`05_touching.png` 里两个圆粘在一起。试一试：对掩膜做腐蚀，直到变成两块；记下这两块的重心。腐蚀多少次可以分开？这个办法有什么限制？
8. **给平台加功能**：给 Blob 算子增加一个输出或给 `Blob` 增加字段，提供圆度和长宽比。先写出需要改哪些文件、会影响哪些已有的测试，再动手。
