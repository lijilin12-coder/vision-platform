# 第 3 课：直方图与阈值

> 预计用时：2.5 小时
> 示例代码：[`examples/lesson03/`](examples/lesson03/)

## 这一课要回答的问题

要测量零件的面积，或者数一数表面有几个亮斑，第一步都是同一件事：**把图像里的像素分成两类，“是我要的”和“不是我要的”**。这一步叫**分割**。最简单的分割方法是阈值：比某个亮度亮的算一类，其余算另一类。

1. 怎样知道一张图像里亮的、暗的像素各有多少？
2. 阈值取多少？
3. 光线变了怎么办？
4. 光照不均匀怎么办？
5. 这几种方法各自什么时候会失效？

## 1. 直方图

### 1.1 直方图就是计数

**直方图**回答一个问题：每一种灰度的像素各有多少个。

```cpp
std::vector<int> counts(256, 0);
for (int y = 0; y < part.rows; ++y) {
    const uchar* row = part.ptr<uchar>(y);
    for (int x = 0; x < part.cols; ++x) ++counts[row[x]];
}
```

就是竞赛里的“桶计数”。OpenCV 的 `cv::calcHist` 做的是同一件事（它的参数比较多，示例里包成了一个函数 `grayHistogram`），结果和上面自己数的完全相同。

直方图丢掉了位置信息：它只知道“有 8 万个灰度 70 左右的像素”，不知道它们在哪里。

### 1.2 读直方图

示例图像是第 1 课的零件：浅色背景（灰度 170）上一个深色零件（灰度 70）。它的直方图（`03_histogram_part.png`）横轴是灰度 0～255，纵轴是像素个数：

```
像素个数
   │                                       █
   │                                       █
   │               █                       █
   │               █                       █
   │              ███                     ███
   └──────────────┴────────────────────────┴──────────── 灰度
   0              70                      170        255
                 零件                     背景
```

- **两个峰**：一个在 70（零件），一个在 170（背景）。图像里有两种东西，直方图就有两个峰。
- **峰有宽度**：背景画的是均匀的 170，但加了噪声之后，像素值分布在 170 上下。示例测出背景的标准差是 3.04，正是生成图像时加的噪声大小。真实相机拍出来的图像也是这样，没有哪一块区域是完全均匀的。
- **两个峰之间是“谷”**：示例里灰度 90～150 之间一个像素都没有。

> 这张示例图的边缘是“一刀切”的，所以谷里完全是空的。真实图像的边缘总有一点模糊，零件和背景交界处的像素灰度介于两者之间，谷里会有少量像素。

### 1.3 光线一变，直方图就变

**光线整体变暗**（示例里把图像乘以 0.6，`03_histogram_darker.png`）：背景从 170 变成 102，零件从 70 变成 42。两个峰一起向左移动，并且靠得更近了（相差从 100 变成 60）。

**光照不均匀**（左边亮，右边只有左边的 35%，`03_part_shaded.png`）：

```
左边的背景 168，左边的零件 57，右边的背景 65
```

右边的背景和左边的零件几乎一样暗。直方图（`03_histogram_shaded.png`）里两个峰被拉宽后糊在了一起，再也分不出清楚的两个峰。

记住这三张直方图的样子，后面三种阈值方法的成败都可以用它们解释。

## 2. 固定阈值

```cpp
cv::Mat partMask;
cv::threshold(part, partMask, 120, 255, cv::THRESH_BINARY_INV);
```

| 类型 | 规则 | 得到的是 |
|---|---|---|
| `cv::THRESH_BINARY` | 大于阈值 → 255，其余 → 0 | 亮的东西 |
| `cv::THRESH_BINARY_INV` | 大于阈值 → 0，其余 → 255 | 暗的东西 |

结果是一张**二值图像**：只有 0 和 255 两种值。习惯上**让要找的东西是白色（255）**，后面的函数（数面积、找连通区域）都按这个习惯工作。我们要的是暗的零件，所以用 `THRESH_BINARY_INV`。

阈值 120 取在直方图的谷里。因为示例图像是自己画的，可以检查结果：

```
固定阈值 120：零件面积 85739，真实面积约 85903.1，相差 0.19%
```

阈值取 100 或 140，结果完全一样：谷里没有像素，阈值在谷里怎么移动都不影响结果。**谷越宽，阈值越好选，结果越稳定。** 这也是为什么工业视觉花很大力气在打光上：好的光照让目标和背景的亮度差尽可能大，后面的算法就简单而可靠。

**固定阈值什么时候失效？** 光线变了的时候。

```
光线变暗后仍用阈值 120：307045 个像素被当成零件（整张图共 307200）
```

光线暗到 60% 时，背景变成了 102，也低于 120 了，于是几乎整张图都被当成了零件（`03_darker_fixed_120.png` 是一张全白的图）。

## 3. 大津法：自动选阈值

**大津法**（Otsu，以提出者的名字命名）根据直方图自动选一个阈值。它的想法是：试遍 0～255 每一个可能的阈值，每个阈值都把像素分成两组；选让**两组之间差别最大**的那一个。

```cpp
cv::Mat otsu;
const double value = cv::threshold(part, otsu, 0, 255, cv::THRESH_BINARY_INV | cv::THRESH_OTSU);
```

加上 `cv::THRESH_OTSU` 之后，第三个参数（阈值）被忽略，函数的返回值是它选出的阈值。

```
大津法：原图选了阈值 83，变暗的图选了阈值 50
```

光线变暗，阈值自动从 83 变成 50，分割出的面积误差仍然小于 1%（`03_darker_otsu.png`）。

（阈值 83 不在谷的正中间，这没有关系：谷里没有像素，谷里的任何一个值分出来的两组都相同。）

**大津法什么时候失效？两种情况。**

**① 图像里实际上只有一种东西。** 大津法**总是**把像素分成两组，不管是不是真的有两种东西。示例里对一张只有背景、什么都没有的图像用大津法：

```
空白图像上的大津法：阈值 170，56.6% 的像素被分成“暗的一类”
```

它从噪声的正中间切了一刀，一半多的像素被当成了“目标”（`03_blank_otsu.png` 是满屏的雪花点）。

这在缺陷检测里是致命的。检测亮斑、划痕时，**大多数产品是良品，图像里根本没有缺陷**。这时大津法会在良品上“找到”一大堆并不存在的缺陷。即使有缺陷，缺陷通常只占图像的万分之几，在直方图里形成不了一个峰，大津法也找不准。

所以：**大津法适合“图像里一定有两种东西，而且各占不小的比例”的情况**，比如把零件从背景里分出来。**找缺陷要用固定阈值**（或者相对于背景亮度的阈值），没有缺陷时就应该什么都分不出来：

```cpp
cv::threshold(blank, blankFixed, 120, 255, cv::THRESH_BINARY_INV);   // 一个像素也没有分出来
```

**② 光照不均匀。** 见下一节。

## 4. 光照不均匀：自适应阈值

换一张示例图像：浅色的板子上印着 24 个深色圆点，然后加上从左到右越来越暗的光照（`03_dots_shaded.png`）。

对它用大津法：

```
不均匀光照下的大津法：分出 152495 个像素，圆点实际共 4825
```

打开 `03_dots_otsu.png`：左半边的 12 个圆点被正确分出来了，但整个右半边是一片白，那里的背景比阈值还暗，圆点淹没在里面。

这不是大津法选得不好，而是**不存在任何一个全局阈值能用**：左边的圆点（约 60）比右边的背景（约 70）还暗不了多少，而右边的圆点更暗。一个阈值要么漏掉右边的圆点和背景的区别，要么把右边的背景算进来。

**自适应阈值**的想法：不用同一个阈值，而是让每个像素**和它周围的平均亮度比**。

```cpp
cv::adaptiveThreshold(shadedDots, dotsAdaptive, 255,
                      cv::ADAPTIVE_THRESH_MEAN_C, cv::THRESH_BINARY_INV,
                      51,    // 周围 51×51 的范围
                      10);   // 比周围的平均值暗 10 以上才算
```

对每个像素：计算以它为中心 51×51 范围内的平均灰度，如果这个像素比平均值暗 10 以上，就是 255，否则是 0。

圆点很小，51×51 的范围里大部分是背景，所以“周围的平均亮度”大致就是那一带背景的亮度。不管那里的背景是亮是暗，圆点总是比它周围暗得多。

```
自适应阈值：分出 4748 个像素，和实际相差 1.6%
```

24 个圆点全部被找到（`03_dots_adaptive.png`）。

两个参数怎么选：

| 参数 | 含义 | 怎么选 |
|---|---|---|
| 窗口大小（必须是奇数） | “周围”有多大 | **明显大于要找的东西**（这里圆点直径 16，窗口 51）。太小会出现下面的问题 |
| 常数 C | 比周围暗多少才算 | 大于噪声的幅度。这里噪声标准差是 3，C 取 10。太小则背景上到处是噪声点 |

**自适应阈值什么时候失效？要找的东西比窗口大的时候。**

对第 1 课的大零件用同样的参数：

```
对大零件用同样的自适应阈值：只分出 35156 个像素，零件实际 85903
```

打开 `03_part_adaptive_hollow.png`：零件只剩下边缘的一圈，中间是空的。

原因：在零件的内部，一个像素周围 51×51 的范围里全是零件，它和周围一样暗，不算“比周围暗”。只有靠近边缘的像素，周围才有一部分是亮的背景。

所以自适应阈值适合**找小的东西**（文字、圆点、细线、小的缺陷），不适合分割大块的区域。大块区域遇到光照不均匀，要用别的办法：先估计出背景的亮度分布再把它除掉（第 4 课的练习），或者从根本上改善打光。

## 5. 三种方法的对照

| | 固定阈值 | 大津法 | 自适应阈值 |
|---|---|---|---|
| 阈值 | 人给定一个 | 根据整张图的直方图自动选一个 | 每个像素各有一个 |
| 光线整体变化 | ✗ | ✓ | ✓ |
| 光照不均匀 | ✗ | ✗ | ✓ |
| 图像里没有目标时 | ✓ 什么都分不出来 | ✗ 仍然硬分成两类 | ✓ 基本分不出来 |
| 目标很大 | ✓ | ✓ | ✗ 被掏空 |
| 目标很小（占比很低） | ✓ | ✗ 形成不了峰 | ✓ |
| 典型用途 | 光照稳定的产线；找缺陷 | 把零件和背景分开 | 文字、标记点、小缺陷 |

没有哪一种是最好的。选择的依据是：**目标占多大比例、光照稳不稳定、均不均匀、目标会不会不存在**。

还有一条比选算法更重要：**能用光照和机械解决的问题，不要留给算法。** 产线上光源是固定的、有遮光罩、亮度可以控制。光照稳定而均匀时，一个固定阈值就够了，而且它是三种方法里最快、最容易解释、行为最可预测的。

## 6. 和平台的关系

平台的 `threshold` 算子（[`operators/src/threshold.cpp`](../../../operators/src/threshold.cpp)）有三个参数：

| 参数 | 对应这一课的 |
|---|---|
| `method`：`fixed` 或 `otsu` | 第 2 节、第 3 节 |
| `value` | 固定阈值的值 |
| `invert` | `THRESH_BINARY_INV`：取暗的区域 |

读一遍它的 `execute` 函数，现在每一行都应该能看懂了。其中有第 1 课讲的 ROI 用法：`src(area)` 取出图像的一块，只对这一块做阈值分割。

它目前没有自适应阈值。给它加上这个方法是一个合适的练习（练习 6）。

## 8. 练习

1. **手写阈值**：不用 `cv::threshold`，自己写循环实现 `THRESH_BINARY_INV`，用 `cv::absdiff` 和 `cv::countNonZero` 确认结果和 OpenCV 的完全相同。
2. **不均匀光照下的零件**：对 `03_part_shaded.png` 分别用固定阈值 120、大津法、自适应阈值，保存三张结果。每一种错在哪里？对照第 5 节的表格解释。
3. **找划痕**：零件上有一道亮的划痕（灰度约 230）。用固定阈值把它分出来，数出像素数。再对一张没有划痕的图（自己用 `cv::rectangle` 画一个）用同样的阈值，确认什么都分不出来。然后改用大津法，看看在没有划痕的图上会得到什么。
4. **调自适应阈值的参数**：在 `03_dots_shaded.png` 上，把窗口大小依次改成 11、21、51、151，把 C 依次改成 2、10、30，观察结果。窗口取 11 时圆点变成了什么样？C 取 2 时背景上出现了什么？
5. **手写大津法**（进阶）：对每个可能的阈值 t，把像素分成“不大于 t”和“大于 t”两组，计算 `w0 × w1 × (m0 − m1)²`，其中 w0、w1 是两组各占的比例，m0、m1 是两组各自的平均灰度；取这个值最大的 t。先算出直方图，再在直方图上做（不需要每次遍历图像）。和 `cv::threshold` 返回的阈值比较。
6. **给平台加功能**：给 `threshold` 算子的 `method` 增加一个选项 `adaptive`，以及它需要的两个参数。参考 [如何新增一个算子](../../dev/how-to-add-operator.md)，并为它写一个测试。注意：修改已有算子的参数涉及算子的版本（设计决定 D5-1），先想一想这次改动需不需要升主版本号。
7. **设计题**：产线上相机拍的是传送带上的金属零件，光源用久了会慢慢变暗（几个月里降低 20%）。检测内容是“零件表面有没有亮斑”。用固定阈值会出什么问题？用大津法呢？你会怎么设计？（提示：能不能利用“零件本体的亮度”作为参照？）
