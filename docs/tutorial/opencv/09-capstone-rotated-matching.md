# 第 9 课：大作业——带旋转角度的模板匹配

> 预计用时：3～4 周（业余时间）
> 代码位置：[`examples/capstone/`](examples/capstone/)
> 需要先学完第 1～8 课

## 1. 任务

零件每次放到相机下面，位置和角度都不一样。写一个函数，在图像里找出零件的**位置**和**角度**；零件不在画面里时，明确回答“没找到”。

```cpp
std::optional<RotatedMatch> findRotated(const cv::Mat& scene, const cv::Mat& templ, const MatchOptions& options = {});
```

这是产线上几乎所有检测和测量的第一步，叫**定位**。知道了零件在哪里、转了多少度，才能把卡尺、检测区域放到零件上正确的位置。商业视觉软件里，定位工具是最核心、最值钱的部分之一。

这个作业把前面八课的内容全部用上：

| 用到的内容 | 来自 |
|---|---|
| 图像、ROI、共享与复制 | 第 1 课 |
| 浮点图像（得分图） | 第 2 课 |
| 掩膜 | 第 2、7 课 |
| 腐蚀（收缩掩膜） | 第 4 课 |
| 角度的约定；Blob 方向的局限 | 第 5 课 |
| 抛物线插值到亚像素 | 第 6 课 |
| 旋转、放大画布、有效区域、金字塔、由粗到细 | 第 7 课 |
| 模板匹配、得分门限、候选 | 第 8 课 |

## 2. 接口

接口定义在 [`examples/capstone/rotated_match.h`](examples/capstone/rotated_match.h)，**不要改它**（评分程序依赖它）。要点：

```cpp
struct RotatedMatch {
    double x, y;     // 模板中心在场景里的位置（像素，可以是小数）
    double angle;    // 目标相对于模板转过的角度。度；[0, 360)；屏幕上顺时针为正
    double score;    // 相似程度，-1～1
};

struct MatchOptions {
    double minScore = 0.7;      // 得分低于它，就认为没有找到
    double angleStart = 0;      // 搜索的角度范围：从 angleStart 开始，
    double angleExtent = 360;   // 顺时针方向一共 angleExtent 度
};
```

三个约定，写代码之前先读两遍：

1. **模板中心**是模板图像的 `(templ.cols / 2.0, templ.rows / 2.0)`。
2. **角度顺时针为正**（和第 5 课一致）。`cv::getRotationMatrix2D` 是逆时针为正（第 7 课）。你的代码里一定有一处要取负号，**把它集中在一个函数里**。
3. 找不到时返回 `std::nullopt`，而不是一个得分很低的结果。

你的实现写在 [`examples/capstone/student/rotated_match.cpp`](examples/capstone/student/rotated_match.cpp)。它现在是一个能编译的空壳，永远返回“没找到”。

## 3. 评分程序

```bash
cmake --build --preset default
```

```bash
./build/docs/tutorial/opencv/examples/cv09_evaluate_student build/tutorial-out/opencv/capstone-student
```

（Windows 上预设名是 `windows`，程序是 `build\docs\tutorial\opencv\examples\cv09_evaluate_student.exe`。）

评分程序（[`evaluate.cpp`](examples/capstone/evaluate.cpp)）生成四组测试图像。因为图像是程序画的，零件的真实位置和角度是已知的，可以直接算出误差：

| 组 | 内容 | 张数 |
|---|---|---|
| A | 小角度（±10 度以内），没有干扰物 | 10 |
| B | 任意角度（0～360 度），有两个干扰物 | 30 |
| C | 任意角度，光线变暗、对比度降低、噪声更大 | 20 |
| D | 没有目标，只有干扰物 | 10 |

测试用的零件是第 8 课的“标记件”，干扰物也和第 8 课相同：一个很亮的大矩形，一个和标记件一样大但没有细节的深色矩形。

输出是每一组的通过数、误差和耗时，出错的会逐条列出真实值和你的结果。输出目录里还有几张把你的结果画在场景上的图（绿框是找到的位置和角度），**出问题时先看图**。

### 评分标准

| 等级 | 要求 |
|---|---|
| **及格** | A、B、C 三组全部满足：位置误差 ≤ 1 像素，角度误差 ≤ 0.5 度；D 组全部返回“没找到” |
| **优秀** | 在及格的基础上：最大位置误差 ≤ 0.3 像素，最大角度误差 ≤ 0.2 度 |
| **速度** | 不设硬指标，但要在报告里给出每个阶段的耗时，并解释为什么变快了 |

空壳现在的成绩是 A、B、C 全部 0 分，D 组 10/10（它什么都“没找到”，在 D 组上碰巧是对的）。

## 4. 分四个阶段完成

**不要一上来就写最终的版本。** 每个阶段都能运行、能评分，每个阶段解决一个问题。下面每个阶段都给出了目标、提示，以及参考实现的作者在这一步实际量到的数字，供你对照。

### 阶段一：最直接的做法，先得到正确的结果

**做法**：对每个角度（0、1、2、……、359 度），把模板旋转到这个角度，做一次模板匹配，记下最高分和位置。取得分最高的那一次。

**第一步，先不处理四个角**，直接用旋转后的模板去匹配。在一张目标转了 37.3 度、位置在 (300.4, 190.7) 的场景上，你会得到类似这样的结果：

```
不带掩膜：位置 (110, 390)，角度 0 度，得分 0.654
```

**完全错了。** 它找到了那个没有细节的深色矩形上。原因是第 7 课第 3.2 节讲的：旋转后的模板四个角是填充的黑色，带着黑角去匹配，等于要求目标周围也是黑的，真正的目标反而得分不高。

**第二步，加上掩膜。** `cv::matchTemplate` 的第五个参数是掩膜：掩膜为 0 的像素不参与计算。掩膜怎么得到，第 7 课讲过：对一张全白的图做同样的旋转。

```
带掩膜：位置 (300, 191)，角度 37 度，得分 0.969，耗时 12.3 秒
```

对了。但是一张 640×480 的图要 12 秒。

提示：

- 带掩膜的匹配，在模板盖住的图像完全均匀的地方，得分的分母是 0，结果会是无穷大或者“不是一个数”（NaN）。`cv::minMaxLoc` 会把它们当成最大值。**取最高分之前，必须先把这些异常值处理掉**（`cv::patchNaNs`，以及把大于 1 的值改掉）。这是这个作业里最隐蔽的坑。
- 旋转之后模板变大了（第 7 课的画布公式）。得分图里的坐标是旋转后模板**左上角**的位置，换成中心要加的是**旋转后**模板的一半。
- 掩膜的边缘向里缩一圈（腐蚀），因为最边上的像素是模板内容和填充值插值出来的。
- 每个角度都从**原始模板**旋转，不要在上一个角度的结果上接着转（第 7 课第 3.3 节）。

**这个阶段的目标**：B 组全部及格可能还做不到（角度只精确到 1 度，误差最大 0.5 度，正好在及格线上），但位置和角度应该基本正确。耗时很长是正常的，评分时可以先把 `evaluate.cpp` 里的张数临时改小。

### 阶段二：用金字塔加速

**做法**：

1. 场景和模板都建金字塔。
2. 在最高层（最小的图）上，用较大的角度步长，试遍所有角度。
3. 把结果换算到下一层：位置乘以 2，只在周围几个像素的范围里找；角度只试“上一层的结果 ± 一步”，同时把步长减半。
4. 一层一层往下，直到原图。

提示：

- **用到第几层？** 最高层上模板必须还认得出来（第 7 课第 4.5 节）。参考实现要求最高层上模板的短边不小于 12 个像素。这个数是试出来的，你也要自己试。
- **粗找的角度步长取多少？** 步长的选择应该让模板最外面的像素每一步移动大约 1 个像素。模板越小，步长可以越大。在最高层上模板很小，所以步长可以比较大（参考实现在这个例子里是 4.6 度）。第 8 课的练习 7 让你量过“转多少度得分还能保持”，现在用得上了。
- **保留几个候选。** 最高层上细节很少，没有细节的深色矩形和真正的目标得分可能很接近，第一名不一定是真的。稳妥的做法是粗找之后保留得分最高的几个（参考实现留 5 个），都往下细找，到细节多的层上再比较。说明一下实际情况：在这套测试图像上，参考实现只留一个候选也全部正确（我们试过，还快了约四分之一）。保留多个是为更难的情况留的余量：金字塔用得更高、干扰物和目标更像时。这个余量值不值，请你自己做实验判断（比如多加一层金字塔，再比较留 1 个和留 5 个）。
- 每往下一层，细节更多，真假更容易分清。得分明显落后的候选可以丢掉，省时间。
- 细找的小窗口可能伸到图像外面，要和图像范围求交集（第 1 课），并且检查求交集之后还放不放得下模板。

**这个阶段的目标**：结果和阶段一相同，耗时从十几秒降到 0.1 秒左右。在报告里解释这一百多倍是从哪里来的。

### 阶段三：提高精度

到这里，角度的精度受限于最小的角度步长，位置的精度是 1 个像素。

**做法**：第 6 课的抛物线插值。

- **角度**：最高分的角度，加上它两侧各一个角度的得分，三个点确定一条抛物线，取顶点。
- **位置**：最高分位置左右两个得分插值出 x，上下两个得分插值出 y。

提示：

- 插值之前要先确认中间那个点确实是最高的。如果旁边的角度得分更高，先挪过去。
- **角度插值的间隔不要取得太小。** 参考实现最初用 0.5 度的间隔，最大角度误差是 0.45 度；改成 0.25 度，反而变成了 0.50 度。原因是相邻两步的得分差太小，被噪声盖住了。把插值的间隔放宽到 1.5 度（取最高分两侧各 1.5 度的得分），最大误差降到 0.17 度。**这是一个只有测量才能发现的问题**，记得在你的实现上也做这个实验。
- 分母为 0、或者三个点不构成一个“峰”时，不要插值。

**这个阶段的目标**：达到优秀线。

### 阶段四：可靠性

用 C 组和 D 组检验：

- 光线变暗、噪声变大时，结果还对吗？得分降了多少？
- 没有目标时，返回的是“没找到”吗？最高的得分是多少，离 `minScore` 有多远？
- 目标靠近图像边缘、旋转后的模板放不下时，程序会不会崩溃？（评分程序没有测这一项，自己构造几张图试。）
- 输入不合法（空图像、彩色图像、模板比场景大）时，函数应该返回“没找到”还是别的？在报告里说明你的选择和理由。

## 5. 参考实现的成绩

参考实现在 [`examples/capstone/reference/rotated_match.cpp`](examples/capstone/reference/rotated_match.cpp)。**建议先自己做完再看。** 自己卡了很久的地方，看到别人怎么解决时收获最大；直接看答案，这个作业就只剩抄写了。

它的成绩（Linux 开发机，640×480 的场景，168×108 的模板）：

| 组 | 及格 | 位置误差（平均 / 最大） | 角度误差（平均 / 最大） | 耗时（平均 / 最大） |
|---|---|---|---|---|
| A 小角度 | 10 / 10 | 0.04 / 0.09 像素 | 0.05 / 0.11 度 | 55 / 75 毫秒 |
| B 任意角度 | 30 / 30 | 0.04 / 0.13 像素 | 0.03 / 0.09 度 | 81 / 112 毫秒 |
| C 变暗加噪声 | 20 / 20 | 0.06 / 0.15 像素 | 0.04 / 0.19 度 | 91 / 125 毫秒 |
| D 没有目标 | 10 / 10 正确 | | | |

另外在 200 张随机场景上测过：全部找对，角度误差最大 0.17 度。

参考实现**不是**最好的做法，只是一个清楚的、够用的做法。它至少有这些可以改进的地方：

- 每次都重新旋转模板、重新建金字塔。模板是固定的，这些可以只做一次（“训练”），以后每张图直接用。
- 带掩膜的匹配比普通匹配慢很多。
- 每张图 80 毫秒，对产线来说偏慢。

所以你完全可能做得比它更快、更准。

## 6. 调试建议

这个作业里，“结果不对”的原因有很多种。按下面的顺序排查，能省很多时间：

1. **先看图。** 把找到的位置和角度画在场景上。位置对、角度反了（比如 37 度变成 323 度），是角度符号的问题。位置偏了固定的一段距离，是“左上角还是中心”“旋转前的大小还是旋转后的大小”的问题。
2. **用最简单的场景。** 没有干扰物、没有噪声、角度是 0。先让它对，再加角度，再加干扰物。
3. **用已知的角度验证符号。** 目标转 +30 度（顺时针）时，你的函数返回的是 30 还是 330？
4. **把“角度—得分”的曲线打印出来。** 在正确的位置上，每个角度的得分是多少？峰在哪里？峰有多尖？有没有 NaN 或者大于 1 的值？
5. **逐层检查。** 最高层上找到的大致位置对不对？换算到下一层之后对不对？问题通常出在某一层的坐标换算上。
6. **用调试器**（C++ 教程第 12 课）和 AddressSanitizer（第 13 课）。ROI 越界时 OpenCV 会抛异常，看调用栈找到是哪一个 ROI。

## 8. 进阶（选做）

按难度递增：

1. **“训练”和“查找”分开。** 把接口改成一个类：构造时传入模板，把各个角度、各层的旋转模板和掩膜都预先算好；`find(scene)` 时直接用。量一量快了多少。想一想预先算好的数据占多少内存，值不值（C++ 教程第 14 课延伸篇讲过这类取舍）。
2. **找多个目标。** 场景里有好几个零件，全部找出来。要在“位置加角度”的三维空间里做非极大值抑制：位置很近、角度也很近的结果是同一个目标。
3. **限定角度范围。** 用上 `MatchOptions` 里的 `angleStart` 和 `angleExtent`。很多产线上零件的角度变化只有 ±15 度，搜索范围小了能快多少？
4. **用多线程。** 粗找时各个角度之间互不依赖，可以交给线程池（C++ 教程第 16 课延伸篇）。注意 OpenCV 自己内部也可能在用多线程，测量时要小心。
5. **做成平台的算子。** 见下一节。
6. **基于边缘的匹配**（研究性质）。本作业比较的是灰度。商业软件里更常用的是比较边缘的位置和方向（第 6 课的梯度方向），对光照变化、局部遮挡更不敏感，也更快。可以查资料了解“基于形状的匹配”，试着实现一个最简单的版本，和灰度匹配对比。

## 9. 做成平台的算子

这是把大作业接到项目上的一步，需要和哥哥一起设计。动手之前先把下面几个问题想清楚，写成一页设计说明：

| 问题 | 说明 |
|---|---|
| **输出是什么类型？** | 位置加角度，这在视觉软件里叫“位姿”。共享内核里现在没有这种类型（只有图像、区域、Blob 列表、数值、判定）。要新增一个值对象，并且新增一种端口类型 |
| **模板存在哪里？** | 模板是一张图像，不是数字。它应该是方案版本的一部分，发布之后不能变；要能随着上线包带到另一台机器。参考模型文件的做法（按内容寻址存放） |
| **“没找到”算什么？** | 是节点执行失败（检测结果为 ERROR），还是一种正常的输出（后面的判定节点据此判为不合格）？零件没放到位和程序出错是两回事。参考设计文档里关于判定的规则 |
| **后面的算子怎样使用位姿？** | 卡尺、阈值的检测区域是在模板上画的。零件转了 30 度，检测区域也要跟着转。是每个算子都接收一个位姿输入，还是先把图像“摆正”再交给后面的算子？各有什么代价（第 7 课：摆正要重新插值，会损失一点清晰度） |
| **训练在什么时候做？** | 预先计算旋转模板（进阶 1）应该在方案发布时、上线包加载时，还是第一次检测时？这关系到热切换时的预热 |
| **跨平台一致性** | 同一个方案在开发机和鸿蒙电脑上，找到的位置和角度允许相差多少？这要写进一致性检查的标准 |

这些问题没有标准答案。把你的方案和理由写出来，本身就是很好的答辩材料。

## 10. 答辩时可能被问到的问题

做完之后，试着不看代码回答：

1. 为什么不用 Blob 的方向来确定角度？
2. 普通的模板匹配，目标转多少度就不行了？为什么？
3. 旋转模板之后为什么要用掩膜？不用会怎样？你是怎么发现的？
4. 带掩膜的匹配结果里为什么会出现 NaN？你是怎么处理的？
5. 金字塔为什么能加速？一共快了多少倍？这些倍数分别来自哪里？
6. 金字塔用到第几层是怎么决定的？再高一层会怎样？
7. 粗找的角度步长是怎么决定的？
8. 粗找之后保留几个候选？只留一个会在什么样的情况下出错？你是用什么实验确定的？
9. 角度是怎样精确到小于一个步长的？插值的间隔为什么不是越小越好？
10. 怎么知道你的结果是对的？测试图像是怎么来的？用程序画的图像做测试有什么局限？
11. 你的实现在什么情况下会失败？
