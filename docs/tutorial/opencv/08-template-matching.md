# 第 8 课：模板匹配

> 预计用时：3 小时
> 示例代码：[`examples/lesson08/`](examples/lesson08/)

## 这一课要回答的问题

第 5 课的 Blob 分析能告诉我们物体在哪里、朝哪个方向，但有两个前提：物体能被干净地分割出来，而且形状简单。很多零件不满足：表面有图案，形状接近方形，或者和背景对比不明显。

换一个思路：**事先存一张零件的图片，在新拍的图像里找“和这张图片最像的地方”。** 这就是模板匹配。

1. “像”怎么计算？
2. 几种计算方法有什么区别，该用哪一种？
3. 怎么知道找到的是真的，而不是凑巧有点像？
4. 一张图里有好几个目标怎么办？
5. 太慢了怎么办？
6. 它最大的弱点是什么？

## 1. 基本做法

### 1.1 滑动窗口

把模板（一张小图）放在大图的左上角，算一个“相似程度”的分数；向右挪一个像素，再算一次；一行挪完换下一行……直到把所有位置都试过。

```
┌──────────────────────────┐
│┌────┐→                   │     模板放在每一个可能的位置上，
││模板│  →  →  →           │     各算一个得分
│└────┘                    │
│   ↓                      │
│                          │
└──────────────────────────┘
```

```cpp
cv::Mat result;
cv::matchTemplate(scene, templ, result, cv::TM_CCOEFF_NORMED);
```

`result` 是一张“得分图”：

```
场景 640×480，模板 168×108，结果图 473×373，类型是 32 位浮点数
```

- **大小是 场景 − 模板 + 1**：模板必须完整地落在图像里，所以能放的位置比图像小一圈。
- **类型是 `CV_32FC1`**：每个像素是一个 `float`（第 2 课），表示“模板的左上角放在这里时的得分”。

打开 `08_score_map.png`：这是得分图（越亮得分越高）。有一个很小的亮点，那就是模板和零件对上的位置。

### 1.2 找出最高分

```cpp
double minValue, maxValue;
cv::Point minLocation, maxLocation;
cv::minMaxLoc(result, &minValue, &maxValue, &minLocation, &maxLocation);
```

`maxLocation` 是得分最高的位置。注意它是**模板左上角**的坐标。习惯上用模板中心表示目标的位置：

```cpp
const double centerX = maxLocation.x + templ.cols / 2.0;
const double centerY = maxLocation.y + templ.rows / 2.0;
```

```
最高分 0.983，位置 (250, 150)；真实位置 (250, 150)
```

示例图像里的零件是一个不对称的“标记件”（`08_template.png`）：深色的矩形，上面有一个圆孔、一个小方孔、一条灰色的线，左上角切掉一个角。场景里还有两个干扰物：一个很亮的大矩形，一个和标记件一样大但没有任何细节的深色矩形（`08_scene.png`）。

## 2. “像”怎么算

`matchTemplate` 的最后一个参数选择计算方法。有三种基本思路，每种有“归一化”和“不归一化”两个版本。

### 2.1 平方差：`TM_SQDIFF`

最直接的想法：把模板和它盖住的那块图像逐像素相减，平方，加起来。

```
得分 = Σ (模板的像素 − 图像的像素)²
```

完全一样时是 0，越不像越大。**注意它是越小越好**，要取 `minLocation`，和其他方法相反。写错了不会报错，只会找到最不像的地方。

### 2.2 相关：`TM_CCORR`

把模板和图像逐像素**相乘**，加起来。

```
得分 = Σ (模板的像素 × 图像的像素)
```

直觉是：亮的对亮的、暗的对暗的时，乘积之和最大。但它有一个严重的问题：

```
相关 TM_CCORR（不归一化）：位置 (523, 390)
```

找到了那个很亮的大矩形上。因为图像越亮，乘积就越大，**哪里亮哪里得分高**，和像不像没有关系。不归一化的相关基本不能直接用。

### 2.3 归一化相关系数：`TM_CCOEFF_NORMED`

对上面的做法做两处修正：

1. **先各自减去平均值**：模板减去模板的平均灰度，图像的那一块减去它自己的平均灰度。这样比较的是“明暗的起伏”，整体偏亮还是偏暗不再有影响。
2. **再除以各自的起伏大小（归一化）**：这样对比度强还是弱也不再有影响。

结果是一个 −1 到 1 之间的数：

| 得分 | 含义 |
|---|---|
| 1 | 明暗的图案完全一致 |
| 0 | 没有关系 |
| −1 | 图案正好相反（模板亮的地方图像暗） |

这个量在统计学里叫**相关系数**。

### 2.4 光线变了

把场景整体变暗并降低对比度（`scene * 0.6 + 20`）：

```
光线变化之后：平方差的最小值从 1.06e+06 变成 1.18e+07；归一化相关系数从 0.983 变成 0.983
```

- 平方差：位置还是对的，但数值变了十倍多。**没法定一个固定的门限来判断“这个分数算不算找到了”。**
- 归一化相关系数：得分和位置都几乎不变。

和第 6 课边缘的道理一样：比较“变化的图案”，而不是“亮度的绝对值”，就不怕光线变化。

### 2.5 用哪一种

| 方法 | 最好的值 | 光线整体变化 | 说明 |
|---|---|---|---|
| `TM_SQDIFF` | 最小 | ✗ | 光照完全稳定时可以用；最快 |
| `TM_CCORR` | 最大 | ✗ | 哪里亮哪里得分高，一般不用 |
| `TM_CCORR_NORMED` | 最大 | 部分 | 没有减去平均值，分数普遍偏高，区分度差 |
| **`TM_CCOEFF_NORMED`** | 最大 | ✓ | **默认用它**。得分在 −1～1 之间，含义清楚 |

## 3. 得分：判断“有没有”

模板匹配**总会**给出一个最高分的位置，哪怕图像里根本没有目标。

```
场景里没有标记件：最高分 0.654，位置 (110, 390)
```

没有标记件的场景里，最高分是 0.654，位置在那个没有细节的深色矩形上。它和模板一样大、一样暗，“大体上”是像的，只是缺少里面的圆孔、方孔和标记线。

所以必须设一个**最低得分**，低于它就报告“没找到”。这里可以取 0.8：真的目标是 0.98，最像的干扰物是 0.65。

两点提醒：

- **0.65 不低。** 一个只是外形相同的东西就能得到 0.65。模板里“大块的明暗”贡献了大部分分数，细节贡献得少。所以门限不能定得太低，而且要用实际的图像试过：分别看“有目标时最低多少分”和“没有目标时最高多少分”，门限取在中间。
- 这是第三次遇到同一个原则了（第 3 课的大津法、第 6 课的卡尺）：**检测工具必须能说“没有”。**

## 4. 找多个目标

场景里有三个标记件。只取最高分只能找到一个。

得分图上每个目标对应一个峰。但不能简单地“取所有大于 0.8 的位置”：峰不是一个点，真实位置旁边一两个像素的得分也很高，一个目标会被报告很多次。

做法是**取一个，抹一片**：

```cpp
while (true) {
    cv::minMaxLoc(result, nullptr, &maxValue, nullptr, &maxLocation);
    if (maxValue < minScore) break;                          // 剩下的都不够像了
    found.push_back(...);
    // 把这个峰周围一个模板大小的范围抹掉：那里的高分都属于同一个目标
    const cv::Rect around(maxLocation.x - templ.cols / 2, maxLocation.y - templ.rows / 2, templ.cols, templ.rows);
    result(around & cv::Rect(0, 0, result.cols, result.rows)).setTo(-1);
}
```

```
三个标记件的场景：找到 3 个  (420, 120) 得分 0.983  (130, 90) 得分 0.983  (300, 270) 得分 0.983
```

这个做法叫**非极大值抑制**：每个峰只留最高的那一点。第 6 课 Canny 把边缘变成一个像素宽，用的是同一个思想。

结果画在 `08_scene_three_found.png` 上。代码里用到了第 1 课的两个技巧：`result(…)` 取 ROI 再 `setTo`，以及用 `&` 把矩形限制在图像范围内。

## 5. 太慢了：用金字塔

模板匹配的计算量大致是“位置数 × 模板的像素数”。一张 1920×1440 的图像配一个 504×324 的模板：

```
大图 1920×1440：直接匹配 117 毫秒；由粗到细 6.1 毫秒
```

（Linux 开发机上的数字，你的机器上会不同。）

用第 7 课的由粗到细：

```cpp
// 1. 场景和模板都缩小到 1/8（第 3 层）
for (int i = 0; i < 3; ++i) {
    cv::pyrDown(smallScene, smallScene);
    cv::pyrDown(smallTempl, smallTempl);
}

// 2. 在小图上做完整的匹配：得到大致位置
const Match coarse = bestMatch(smallScene, smallTempl);

// 3. 换算回原图（乘以 8），只在周围一个小窗口里用原始大小的模板再匹配一次
const cv::Rect window = /* 模板大小，四周各多出 16 个像素 */;
Match fine = bestMatch(bigScene(window), bigTempl);
fine.x += window.x;      // 小窗口里的坐标换回整张图的坐标
fine.y += window.y;
```

```
第 3 层上的粗略位置换算回原图是 (748, 452)；最终位置 (750, 450)，和直接匹配相同
```

快了将近 20 倍，结果完全相同。缩小到 1/8 之后，图像的像素数是 1/64，模板的像素数也是 1/64，粗找的计算量只有原来的几千分之一；细找只在 33×33 个位置上做。

三个要点：

- **场景和模板要一起缩小**，而且缩小的方式要相同。
- **细找的窗口要留够余量。** 第 3 层上差 1 个像素，原图上就是 8 个像素。窗口太小，真正的位置可能落在窗口外面。
- **最高层不能太高。**（第 7 课第 4.5 节）模板缩得太小，细节没了，粗找就可能找到干扰物上去，后面的细找只会在错误的地方找出一个“最好”的结果。粗找时最好保留几个候选，而不是只取最高分。

## 6. 模板匹配的弱点

### 6.1 最大的弱点：旋转

把标记件转过不同的角度，看最高分：

```
  0 度：得分 0.983，位置误差 0 个像素
  1 度：得分 0.957，位置误差 0 个像素
  2 度：得分 0.908，位置误差 0 个像素
  5 度：得分 0.745，位置误差 1 个像素
  10 度：得分 0.560，位置误差 5 个像素
  20 度：得分 0.483，位置误差 13 个像素
  45 度：得分 0.375，位置误差 25 个像素
  90 度：得分 0.319，位置误差 41 个像素
  180 度：得分 0.387，位置误差 1 个像素
```

- 转 2 度，得分还有 0.91。
- **转 5 度，得分掉到 0.75**，已经低于刚才定的门限 0.8。
- 转 10 度，得分 0.56，比“没有目标时的干扰物”（0.65）还低，位置也偏了 5 个像素。
- 再往上，基本就是乱找了。

原因很直接：模板匹配是**逐像素**比较的。零件转了一个角度，离中心越远的地方移动得越多；160 像素宽的零件转 5 度，边上的像素移动了约 7 个像素，模板上的方孔已经对不上图像里的方孔了。

**模板匹配只能容忍一两度的旋转。** 而产线上零件的摆放角度常常是任意的。

### 6.2 其他弱点

| 问题 | 原因 | 对策 |
|---|---|---|
| 大小变化（相机远近变了） | 同样是逐像素对不上 | 固定安装距离；或者多个尺度的模板 |
| 目标被遮住一部分 | 被遮的部分拉低得分 | 降低门限（有误报的风险）；改用基于边缘的方法 |
| 目标表面没有图案 | 均匀的一块，放哪里都“像” | 模板里必须有足够的明暗变化，最好包含边缘和角 |
| 光照不均匀、局部反光 | 归一化只能抵消整体的明暗变化 | 改善打光；改用基于边缘的方法 |

关于“模板里要有什么”：好的模板应该包含**在两个方向上都有变化**的图案。只有一条竖直边缘的模板，沿着边缘上下移动时得分不变，竖直方向的位置就定不准。

## 7. 怎样处理旋转：大作业的出发点

既然模板转了就认不出来，最直接的办法是：**把模板也转一转。**

```
对每一个角度 θ（比如 0、1、2、……、359 度）：
    把模板旋转 θ 度
    用旋转后的模板做一次模板匹配，记下最高分和位置
取得分最高的那个角度和位置
```

这个办法能得到正确的结果，它就是大作业的第一阶段。但是马上会遇到三个问题，都是前面的课里埋下的：

1. **旋转后的模板四个角是填充的。**（第 7 课第 3.2 节）带着黑角去匹配，等于要求目标周围也是黑的。要用掩膜告诉 `matchTemplate` 哪些像素不算。`matchTemplate` 的第五个参数就是掩膜。
2. **太慢。** 360 个角度就是 360 次模板匹配，每次 100 毫秒就是 36 秒。要用金字塔，而且角度也可以“由粗到细”：先每隔 10 度粗找，再在最好的角度附近每隔 1 度细找。
3. **精度。** 角度步长是 1 度，结果就只精确到 1 度；位置只精确到 1 个像素。要更准，可以像第 6 课那样，用最高分和它两边的分数做抛物线插值。

另外还有一个每一课都提醒过的细节：**角度的正方向。** 示例里统一规定“正的角度是顺时针”（和第 5 课一致），而 `getRotationMatrix2D` 是逆时针为正。`cvtut.h` 里的 `placeOnScene` 就是在这里取了一次负号。大作业里你也要处理这个转换。

这些就是第 9 课的内容。

## 8. 和平台的关系

平台目前没有定位类的算子。模板匹配算子是“先定位，后检测”这条路线的起点：

| | |
|---|---|
| 输入 | 图像 |
| 参数 | 模板（一张图像）、最低得分、最多找几个 |
| 输出 | 位置、得分；没找到时怎样报告，需要和卡尺算子统一考虑 |

有一个新的设计问题：**模板是一张图像，它存在哪里？** 之前算子的参数都是数字、选项这类小东西，可以直接写在方案里。模板图像要随着方案一起保存、一起发布、一起带到另一台机器上。按平台的设计，方案版本发布之后内容不能再变，模板也应该是方案版本的一部分，而且要像模型文件一样按内容寻址存放。这个问题留到大作业做算子时和架构负责人一起定。

## 10. 练习

1. **手写平方差匹配**：不用 `matchTemplate`，自己写四层循环实现 `TM_SQDIFF`（用一张小图和小模板，否则很慢），和 OpenCV 的结果比较。然后估算：640×480 的图像配 168×108 的模板，一共要做多少次减法和乘法？
2. **手写归一化相关系数**：在上一题的基础上实现 `TM_CCOEFF_NORMED`：每个位置上，模板和图像块各自减去平均值，求乘积之和，再除以两者各自的“平方和的平方根”的乘积。和 OpenCV 的结果比较。
3. **门限怎么定**：用不同的噪声（标准差 3、10、20、40）生成有标记件和没有标记件的场景各 10 张（改变 `addNoise` 的种子），分别记录最高分。画一张表。噪声多大时，“有”和“没有”的分数开始分不开？
4. **模板的选择**：只用标记件的一部分做模板，比较三种选择：（a）只有圆孔附近的一块；（b）只有零件中间一块没有任何细节的区域；（c）只有一条竖直的边。各自的得分图是什么样的？哪一种定位最可靠？为什么？
5. **亚像素**：用 `placeOnScene` 把标记件放在 (250.4, 150.7)。直接取最高分的位置误差是多少？仿照第 6 课，在 x 和 y 方向上分别用最高分和两边的分数做抛物线插值，误差降到多少？
6. **金字塔的极限**：把第 5 节的金字塔层数从 3 依次改成 4、5、6。到第几层开始，粗找的位置错了？那一层上模板还剩多大？
7. **数旋转的容忍度**：对标记件转 0～10 度（每 0.5 度一档），画出“角度—得分”的曲线。得分降到 0.9 时是几度？如果以后用“每隔 Δ 度旋转一次模板”的办法，Δ 最大可以取多少，才能保证不管目标是什么角度，最好的那个模板的得分都不低于 0.9？
8. **最直接的旋转匹配**（大作业第一阶段的预演）：按第 7 节的伪代码，每隔 5 度旋转一次模板（先不管四角的填充，直接用 170 填充，因为示例的背景正好是 170），找出 `makeScene({{250, 180, 37}})` 里标记件的位置和角度。结果是多少？用了多长时间？
