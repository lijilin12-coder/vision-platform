## 这一课要回答的问题

## 1. 三份招聘要求

下面是三份有代表性的招聘要求（2026 年 11 月），分别来自做 AI 芯片的公司、做 GPU 的公司和做推理服务的团队。原文很长，这里按内容归类：

| 类别 | 招聘要求里的原话 |
|---|---|
| **语言与系统** | 精通 C/C++，扎实的数据结构与算法功底；熟练掌握 Python，熟悉 PyTorch；熟悉 Linux 开发环境 |
| **体系结构** | 深入理解计算机体系结构，对 CPU/NPU/GPU 的内存层次、指令流水、并行度有清晰认知 |
| **推理运行时** | 熟悉至少一种主流推理框架源码（vLLM、TensorRT-LLM、SGLang、ONNX Runtime）；熟悉显存管理、计算图优化及算子融合技术 |
| **算子与硬件适配** | 高性能算子的开发与性能分析；具备 Kernel 级优化经验；针对特定硬件（国产加速芯片）进行算子适配与性能优化；NPU runtime 开发经验 |
| **模型压缩** | 熟悉常见模型压缩和推理加速算法，如量化、剪枝、蒸馏和投机采样 |
| **大模型结构** | 深入理解 Transformer 架构及经典大模型结构（Qwen、Llama、DeepSeek）及算子 |
| **大模型推理优化** | KV Cache 机制、PagedAttention、Continuous Batching、Speculative Decoding、FlashAttention；负责 Prefill 与 Decode 阶段的全链路性能分析、瓶颈定位及优化 |
| **GPU 编程** | 至少掌握 CUDA、OpenCL、CUTLASS 和 Triton 中的一种，熟练使用 Nsight 等性能分析工具；熟悉 CUDA/CANN 编程 |
| **加分项** | 完整的大模型端侧、边缘侧、云端部署经验；熟悉 AI 编译器技术栈（MLIR、TVM、XLA、Glow）；为 vLLM、SGLang、llama.cpp 等开源项目贡献过代码；熟悉分布式推理 |

先解释几个会反复出现的词：

| 词 | 含义 |
|---|---|
| **推理** | 用训练好的模型计算结果。和它相对的是**训练**（调整模型的权重）。这套教程只讲推理 |
| **算子** | 模型里的一种基本运算，例如卷积、矩阵乘法、注意力。和本项目里“算子”的意思相近：一个有输入、有输出的计算步骤 |
| **kernel** | 一个算子在某种硬件上的具体实现。同一个卷积算子，在 CPU、GPU、NPU 上各有一份 kernel。“Kernel 级优化”就是把这份实现写得更快 |
| **NPU** | 专门用来做神经网络计算的处理器。手机和鸿蒙电脑里的麒麟芯片带有 NPU |
| **token** | 大模型处理文本的基本单位，大约相当于一个词或半个词。大模型一次生成一个 token |
| **Prefill / Decode** | 大模型处理一次请求的两个阶段：先一次性读完整个提示词（Prefill），再一个一个地生成 token（Decode）。第 9 课讲 |
| **吞吐 / 延时** | 吞吐是单位时间处理多少（每秒多少个 token）；延时是一条请求等多久。两者常常要取舍 |

## 2. 这些要求其实是两半

把上面的表再归纳一次，可以分成两半：

**第一半：推理系统的通用能力。** 语言与系统、体系结构、推理运行时、算子与硬件适配、模型压缩。这些对视觉模型和大模型是一样的：ONNX Runtime 跑 ResNet 和 vLLM 跑 Qwen，底下都是“把模型表示成图 → 优化图 → 规划内存 → 调用各硬件上的 kernel”。

**第二半：大模型特有的技术。** Transformer 结构、KV Cache、PagedAttention、Continuous Batching、Speculative Decoding、FlashAttention。它们之所以存在，是因为大模型推理有两个视觉模型没有的特点：

1. **一条请求要算很多次。** 检测一张图像，模型前向一次就结束；生成一段 500 个 token 的回答，模型要前向 500 次，而且每次都依赖前面所有的 token。于是有了 KV Cache（不重复计算）、投机解码（一次多猜几个）。
2. **每条请求的长度不同，而且事先不知道。** 于是攒批变得困难（Continuous Batching），内存也不好预留（PagedAttention）。

## 3. 本项目能覆盖什么

本项目是视觉检测平台。它和第一半的重合很大：

| 要求 | 项目里的落点 | 现状 |
|---|---|---|
| C++、并发、内存、性能分析 | 整个 `core/`；C++ 教程第 13～16 课 | 已有 |
| 计算图、执行计划 | 执行上下文的 [`plan.cpp`](../../../../core/contexts/execution/domain/src/plan.cpp)、[`executor.cpp`](../../../../core/contexts/execution/domain/src/executor.cpp)：方案图 → 执行计划 → 按顺序运行 | 骨架已有，没有优化遍 |
| 计算图优化、算子融合 | 方案图上的优化（例如 `to_gray` 和 `threshold` 合并成一次遍历） | 计划中 |
| 显存（内存）管理 | 图像缓冲区的复用 | C++ 教程 14 延伸讲过，引擎里没做 |
| 推理框架（ONNX Runtime）、端侧部署 | `InferBackend`：开发机用 ONNX Runtime，鸿蒙用 MindSpore Lite | POC-4，未开始 |
| NPU runtime、国产芯片适配 | MindSpore Lite 通过 NNRt 使用麒麟 NPU | POC-4 真机部分 |
| 量化 | 模型工具链的 INT8 量化 | POC-10，未开始 |
| 高性能算子 | `operators/` 里的图像算子；异常检测里的最近邻搜索 | 只有基础算子 |
| 攒批、吞吐与延时 | 多工位共用的推理服务 | C++ 教程第 16 课有示例 |

对第二半，项目几乎覆盖不了：视觉检测用不到自回归生成，也就没有 KV Cache、PagedAttention 这些问题。**这一半必须另开一条支线来学**，这就是教程第二部分。

## 5. 这套教程给不了什么

说清楚边界，免得学完之后高估自己：

1. **GPU 编程的实际经验。** CUDA、Nsight、CUTLASS、Triton 需要一块 NVIDIA 显卡和大量练习。第 13 课只讲概念。教程里所有的性能优化都在 CPU 上做：思路（先测量、看内存访问、看并行度）是相通的，但 GPU 上的具体手法要另学。
2. **真实规模的经验。** 示例里的模型只有几层、几十维，一条请求几毫秒。真实系统里才会遇到的问题（几十 GB 的权重怎么加载、显存碎片、多卡之间的通信）这里遇不到。大作业 B 会让你装上一个真实的小模型，但离线上系统仍然很远。
3. **训练和 PyTorch。** 招聘要求里有“熟悉 PyTorch”。项目路线里有一段是用 Python 训练异常检测模型并导出 ONNX，那是学 PyTorch 的地方，不在这套教程里。
4. **工作年限。** 有的岗位要求 5 年相关经验。教程和项目能给的是“做过、讲得清楚、有代码可看”，这对应届和初级岗位有用，替代不了年限。

教程能给的是：**每一项技术你都亲手实现过最小版本，知道它解决什么问题、代价是什么、怎么测量它的效果，并且读过真实框架里对应的代码。** 面试里被问到“讲讲 PagedAttention”，你讲的是自己写过的东西。
