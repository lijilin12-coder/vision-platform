# 第 1 课：张量与算子——手写一个最小的推理引擎

> 预计用时：2 小时
> 示例代码：就在这个文件夹里，和这份正文放在一起

## 这一课要回答的问题

训练好的模型交到你手里时是一个文件（比如 `.onnx`）。把一张图像送进去、拿到结果的过程叫**推理**，做这件事的程序叫**推理引擎**（ONNX Runtime、MindSpore Lite、TensorRT 都是）。平台的深度学习算子最终都要调用它。

1. 模型文件里到底装着什么？推理引擎拿它做了什么？
2. “张量”“算子”这两个词具体指什么？
3. 一次推理的时间花在哪里？

这一课不用任何框架，用 300 行 C++ 把推理引擎最核心的部分写出来。后面每一课都是在它上面改进。

## 1. 先把框架去掉：推理就是按顺序调用一串函数

用 PyTorch 定义一个小网络大概是这样（看个意思，不需要会 Python）：

```python
x = conv1(image); x = relu(x); x = max_pool(x)
x = conv2(x);     x = relu(x); x = max_pool(x)
x = conv3(x);     x = relu(x); x = max_pool(x)
probs = softmax(fc(x))
```

这一课的示例 [`tiny_cnn.cpp`](tiny_cnn.cpp) 里，同样的事情用 C++ 写出来是：

```cpp
Tensor forward(const Weights& w, const Tensor& image) {
    Tensor x = inftut::conv2d(image, w.conv1W, w.conv1B, 1, 1);  // 1×16×64×64
    x = inftut::relu(x);
    x = inftut::maxPool(x, 2);                                   // 1×16×32×32
    x = inftut::conv2d(x, w.conv2W, w.conv2B, 1, 1);             // 1×32×32×32
    x = inftut::relu(x);
    x = inftut::maxPool(x, 2);                                   // 1×32×16×16
    x = inftut::conv2d(x, w.conv3W, w.conv3B, 1, 1);             // 1×64×16×16
    x = inftut::relu(x);
    x = inftut::maxPool(x, 2);                                   // 1×64×8×8
    x = inftut::linear(x, w.fcW, w.fcB);                         // 1×10×1×1
    return inftut::softmax(x);
}
```

这就是推理的全部：**一串函数，前一个的输出是后一个的输入。** 这里出现了三样东西：

| 名称 | 是什么 | 在上面的代码里 |
|---|---|---|
| **张量**（tensor） | 一块连续的数字，加上“几行几列几层”的形状 | `image`、`x` |
| **算子**（operator） | 一个函数：输入张量，输出张量 | `conv2d`、`relu`、`maxPool`、`linear`、`softmax` |
| **权重**（weight） | 算子用到的、训练得到的常数。也是张量 | `w.conv1W`、`w.fcB` 等 |

所以第一个问题的答案是：模型文件里装着两样东西——**网络的结构**（有哪些算子、怎么连接）和**权重**。训练的目的就是找到一组好的权重；推理时权重固定不变，只是拿来用。

这一课的权重是随机数，所以网络输出的“分类结果”没有意义。没有关系：权重是随机的还是训练出来的，计算过程、耗时、内存占用完全一样，而这一课到第 7 课关心的正是这些。

> 和平台的算子是一个词、两个层次。平台的算子（`operators/` 下的 `threshold`、`blob`）处理的是图像和区域，一个检测方案由几个到几十个算子组成；这里的算子处理的是张量，一个模型由几十到几千个算子组成。**一个模型的整次推理，对平台来说只是一个算子内部的事。**

## 2. 张量：一块内存加上形状

[`tensor.h`](tensor.h) 里的定义：

```cpp
struct Tensor {
    int n = 0;  // 批大小：一次送进来几张图
    int c = 0;  // 通道数
    int h = 0;  // 高
    int w = 0;  // 宽
    std::vector<float> data;  // 按 N、C、H、W 的顺序存放，长度是 n*c*h*w
};
```

你已经熟悉 `Image` 和 `cv::Mat`：一块像素内存加上宽、高、通道数。张量是同一个想法，有三点不同。

**元素是 `float`。** 图像的像素是 0～255 的整数，网络中间的数值是任意大小的小数。（第 6 课的“量化”就是想办法把它们换回 8 位整数。）

**多了一个维度 N。** 一次可以送进去好几张图一起算，叫**批**（batch）。这一课 N 始终是 1。

**通道的排列方式不同。** OpenCV 的彩色图像是“一个像素的 B、G、R 挨在一起”；这里是“先放完第 0 个通道的整张图，再放第 1 个通道的整张图”。这种排列叫 **NCHW**，元素 `(n, c, y, x)` 的下标是：

```cpp
((n * C + c) * H + y) * W + x
```

OpenCV 那种排列叫 NHWC。两种排列装的是同样的数，只是顺序不同；把图像送进模型之前要转换，这是接入推理时最容易出错的地方之一（第 7 课）。

张量的通道数通常比图像多得多。图像是 3 个通道；经过第一层卷积之后是 16 个，第三层之后是 64 个。可以把每个通道理解成“对图像的一种描述”，比如某个方向的边缘有多强。网络越往后，图越小、通道越多。

## 3. 算子：五个函数

全部在 [`ops.h`](ops.h) 里，都是最朴素的写法。先看一遍每个算子做什么：

| 算子 | 做什么 | 形状的变化 |
|---|---|---|
| 卷积 `conv2d` | 拿一个小窗口（卷积核）在图上滑动，每个位置算一次“对应元素相乘再相加” | 通道数变成卷积核的个数 |
| `relu` | 负数变成 0，其他不变 | 不变 |
| 最大池化 `maxPool` | 每 2×2 的小块里取最大的一个 | 宽和高各减半 |
| 全连接 `linear` | 把整个张量看成一个长向量，和权重矩阵相乘 | 变成 N×类别数×1×1 |
| `softmax` | 把一组数变成加起来等于 1 的“概率” | 不变 |

### 卷积

卷积你在 OpenCV 教程第 4 课见过：均值滤波、Sobel 都是“用一个 3×3 的核在图上滑动”。网络里的卷积是同一个运算，区别只有两点：

- 核里的数不是人设计的，是训练出来的；
- 输入有很多个通道，每个输出通道用**一组**核（每个输入通道一个），把所有通道的结果加起来。

```cpp
for (int n = 0; n < x.n; ++n)
    for (int oc = 0; oc < outC; ++oc)               // 每个输出通道
        for (int oy = 0; oy < outH; ++oy)
            for (int ox = 0; ox < outW; ++ox) {     // 每个输出位置
                float sum = bias.data[oc];
                for (int ic = 0; ic < x.c; ++ic)                // 每个输入通道
                    for (int ky = 0; ky < weight.h; ++ky)       // 卷积核的每一行
                        for (int kx = 0; kx < weight.w; ++kx)   // 卷积核的每一列
                            sum += x.at(n, ic, iy, ix) * weight.at(oc, ic, ky, kx);
                y.at(n, oc, oy, ox) = sum;
            }
```

（省略了计算 `iy`、`ix` 和处理边界的几行，完整代码见 `ops.h`。）

**七层循环。** 数一数最里面那一行要执行多少次：

```
输出通道数 × 输出高 × 输出宽 × 输入通道数 × 核高 × 核宽
```

第二层卷积是 32 × 32 × 32 × 16 × 3 × 3 ≈ **472 万次**乘加。记住这个算法，后面估算任何模型的计算量都靠它。

卷积还有两个参数：

- **`pad`**（补零）：在输入四周补几圈 0。3×3 的核配 `pad = 1`，输出和输入一样大。
- **`stride`**（步长）：窗口每次滑动几格。步长 2 时输出的宽高减半。

输出的大小是 `(输入大小 + 2 × pad - 核大小) / stride + 1`。

### 另外四个

`relu` 只有一行：`y[i] = max(0, x[i])`。它的作用是让网络不只是一连串的线性运算（两个线性运算叠在一起还是线性的，叠多少层都没用）。

`maxPool` 把图缩小一半，保留每个小块里最强的那个响应。

`linear` 是矩阵乘向量：`out[j] = bias[j] + Σ weight[j][i] * v[i]`。网络最后用它把特征变成“每个类别的得分”。

`softmax` 把得分变成概率。代码里有一个细节值得看：

```cpp
// 先减去最大值再取指数：结果不变，但不会因为 exp(很大的数) 而溢出
y.data[base + i] = std::exp(x.data[base + i] - biggest);
```

`exp(1000)` 在 `float` 里是无穷大，无穷大除以无穷大是 NaN。减去最大值之后，指数最大是 `exp(0) = 1`。数学上分子分母同时除以了 `exp(biggest)`，结果不变。写数值计算的代码时，这类问题很常见。

### 怎么知道算子写对了

[`ops_test.cpp`](ops_test.cpp) 用能手算的小例子检查每个算子。比如 3×3 的输入配上“左上角和右下角是 1”的 2×2 卷积核，每个输出就应该是“左上角加右下角”：

```cpp
const Tensor x = make(1, 1, 3, 3, {1, 2, 3, 4, 5, 6, 7, 8, 9});
const Tensor diag = make(1, 1, 2, 2, {1, 0, 0, 1});
expectNear("卷积：2×2 的核，不补零", inftut::conv2d(x, diag, zeroBias, 1, 0).data, {6, 8, 12, 14});
```

权重是随机数的网络，输出是一堆看不出对错的小数。**算子的正确性只能靠这种小例子保证**，而且后面每做一次优化都要重新跑一遍。第 5 课把卷积改快时，判断标准就是“和这一课的朴素版本结果一致”。

## 4. 时间花在哪里

运行 `tiny_cnn`（数字来自一台 2.1 GHz 的机器，你的结果会不同，看比例）：

```
输入 1x3x64x64，输出 1x10x1x1
10 个类别的概率：0.031 0.463 0.014 0.016 0.019 0.135 0.031 0.084 0.162 0.045
概率之和 1.0000，最大的是第 1 类

层       输出形状        耗时 ms    占比
conv1    1x16x64x64        2.393   16.7%
relu1    1x16x64x64        0.124    0.9%
pool1    1x16x32x32        0.048    0.3%
conv2    1x32x32x32        6.026   42.2%
relu2    1x32x32x32        0.035    0.2%
pool2    1x32x16x16        0.026    0.2%
conv3    1x64x16x16        5.594   39.1%
relu3    1x64x16x16        0.011    0.1%
pool3    1x64x8x8          0.017    0.1%
fc       1x10x1x1          0.019    0.1%
softmax  1x10x1x1          0.000    0.0%
合计 14.29 ms，其中三个卷积层占 98.0%
```

**三个卷积层占了 98%。** 这不是这个小网络特有的现象：卷积网络的时间几乎都花在卷积上，后面要学的大语言模型的时间几乎都花在矩阵乘法上。这两种运算归根到底是同一件事——大量的“相乘再相加”（第 5 课）。

用上一节的公式核对一下：

| 层 | 乘加次数 | 耗时 |
|---|---|---|
| conv1 | 16 × 64 × 64 × 3 × 9 ≈ 177 万 | 2.4 ms |
| conv2 | 32 × 32 × 32 × 16 × 9 ≈ 472 万 | 6.0 ms |
| conv3 | 64 × 16 × 16 × 32 × 9 ≈ 472 万 | 5.6 ms |
| fc | 10 × 4096 ≈ 4 万 | 0.02 ms |

耗时和乘加次数基本成正比，每毫秒大约 80 万次。注意 conv2 和 conv3：图小了一半（面积是四分之一），但输入、输出通道数各翻一倍，计算量正好不变。

**这个速度是很慢的。** 一个 2.1 GHz 的核心每秒执行几十亿条指令，而这里每秒只做了大约 8 亿次乘加。同样的卷积，ONNX Runtime 这样的引擎要快得多。差距从哪里来、能追回多少，第 5 课会动手测量。

所以第三个问题的答案，也是整个性能优化的出发点：

- **先看哪一层慢**，再谈优化。上面这张表就是 C++ 教程第 14 课说的“粗粒度计时”。
- **优化推理，主要就是优化卷积和矩阵乘法。** 把 `relu` 加快 10 倍，整体快不到 1%。

## 5. 推理引擎比这 300 行多了什么

这一课的代码已经是一个能用的推理引擎，只是每一方面都是最简陋的做法。把它和 ONNX Runtime 对比，就是后面几课的目录：

| 方面 | 这一课的做法 | 真实的引擎 | 哪一课 |
|---|---|---|---|
| 网络结构 | 写死在 `forward` 函数里，换个模型要改代码重新编译 | 从模型文件读出来，是数据 | 第 2 课 |
| 结构能否简化 | 原样执行 | 执行前先改写：合并、删除多余的算子 | 第 3 课 |
| 中间结果的内存 | 每个算子返回一个新申请的张量 | 事先规划好，推理时不申请内存 | 第 4 课 |
| 算子的实现 | 七层循环 | 针对每种 CPU、GPU、NPU 专门优化 | 第 5 课 |
| 数值类型 | 32 位浮点 | 可以换成 8 位整数 | 第 6 课 |
| 在什么硬件上算 | CPU | 同一个模型可以交给不同的后端 | 第 7 课 |

关于第四行，有一个词要认识：在 ONNX Runtime 的源码里，某个算子在某种硬件上的一份具体实现叫 **kernel**（注意它和“卷积核”“操作系统内核”都没有关系）。同一个 `Conv` 算子，有 CPU 上的 kernel、CUDA 上的 kernel、NPU 上的 kernel。这一课的 `conv2d` 就是一个 kernel——最慢的那种。岗位要求里的“高性能算子开发”“Kernel 级优化”，指的就是把这些函数写快。

## 6. 和项目的关系

平台目前的算子都在 [`operators/src/`](../../../../operators/src/) 下，是传统图像处理（灰度、阈值、Blob）。深度学习算子（缺陷分类、异常检测）还没有实现，计划是这样的（[技术架构](../../../02-architecture.md)）：

```
方案里的一个节点（比如“异常检测”算子）
        │  把图像转成张量（缩放、归一化、BGR 转 NCHW）
        ▼
   InferBackend 接口 ──► ONNX Runtime（开发机、Windows）
                    └──► MindSpore Lite（鸿蒙，可以用 NPU）
        │  把输出的张量变成区域、得分
        ▼
   节点的输出
```

`InferBackend` 是一个接口（C++ 教程第 8 课）：平台只说“用这个模型算一下这个张量”，具体由哪个推理引擎来算，由适配器决定。这一课写的东西，相当于 `InferBackend` 后面那个方框的内部。

平台不会自己写推理引擎，那为什么要学它的内部？因为接入之后遇到的问题都在内部：

- 同一个模型在两个引擎上输出不一样（POC-4 要验证的就是这个），要能判断差在哪一层；
- 模型在 NPU 上比预期慢，要能看懂“哪些算子没有被 NPU 支持、退回了 CPU”；
- 量化之后精度下降，要知道从哪里查起。

## 8. 练习

1. **手算一次卷积**：输入是 `ops_test.cpp` 里那个 3×3 的 1～9，卷积核是 3×3 的 `[0 0 0; 0 1 0; 0 0 0]`（只有中心是 1），`pad = 1`。先在纸上写出输出，再在 `ops_test.cpp` 里加一条检查验证。
2. **估算再测量**：把 `tiny_cnn.cpp` 的输入从 64×64 改成 128×128（`fcW` 的大小和 `main` 里的图像要跟着改）。先用乘加次数的公式估算总耗时会变成多少倍，再运行验证。
3. **不优化有多慢**：用 `-O0`（Windows 上 `/Od`）编译 `tiny_cnn.cpp`。总耗时变成了多少倍？卷积的占比变了吗？
4. **换一下循环的顺序**：`conv2dInto` 现在是“对每个输出元素，把它需要的输入都加起来”。改写成另一种顺序：先把输出全部填成偏置，然后循环顺序改为“输出通道 → 输入通道 → 核的行 → 核的列 → 输出的行 → 输出的列”，最里面一行是 `y[...] += x[...] * 一个权重`。用 `ops_test` 确认结果不变，再测一下速度。先猜它会变快还是变慢，为什么？（第 5 课会回到这个问题。）
5. **加一个算子**：实现平均池化 `avgPool`（每个小块取平均值），并给它写两条检查。
