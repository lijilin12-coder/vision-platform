# 18 短期图像缓存

> 状态：已实现（2026-11-25）。对应走查发现 **F-3**、需求 QUA-01 的后一半（“漏检时从缓存找回图像”）。
> 设计里把它放在 BC-9 数据；现在平台的产线一侧没有数据上下文，先放在 **BC-10 质量分析**（见 §6 第 4 条）。

## 1. 要解决什么

图像比检测记录大得多（一条记录几百字节，一幅图像几百 KB），不能都永远留着。以前的办法是只留判 NG 和 ERROR 的。

问题在漏检：**漏检恰恰是判了 OK 的那些**。判 OK 的一幅都不留，事后发现漏检时已经无图可看——能复判，但看不到当时的图像，也没法拿它去改方案。

办法：判 OK 的图像**先留一段时间**，够人回头来复判；过期了自动清掉。

## 2. 规则

| 编号 | 内容 |
|---|---|
| M1 | 判 NG、ERROR 的图像**长期保留** |
| M2 | 判 OK 的图像进**短期缓存**，过了保留期（默认 72 小时）清掉 |
| M3 | **复判过**的检测，图像转成长期保留——不管复判的结论是什么。人看过、下过结论的，是以后改方案的材料 |
| M4 | 清理只删图像，**不动检测记录**（Q1）。记录上看得出它的图像“已经过期” |

规则在领域层（`ImageRetention`，`core/contexts/quality/domain/image_retention.h`）。

一条记录的图像有四种情况：

| `imageState` | 意思 |
|---|---|
| `kept` | 长期保留着 |
| `cached` | 在短期缓存里：现在看得到，会过期；复判之后转成 `kept` |
| `expired` | 已经清掉了 |
| `none` | 当时就没留 |

## 3. 存在哪里

```
<数据目录>/inspection-images/<工位 ID>/kept/<记录编号>.png            长期保留
<数据目录>/inspection-images/<工位 ID>/cache/<日期>/<记录编号>.png    短期缓存
```

- **不放进内容仓库。** 内容仓库是按内容哈希存放的，同一份内容可能被好几处引用（样本、模板、基准图集……），没法安全地删。检测图像的大多数是要删的，所以单独放。
- **图像的编号就是检测记录的编号。** 记录编号的前 13 位是时间，由它能算出是哪一天的目录，不用另外记“图像在哪”。
- **按天分目录**：整天都过期的，一个目录一起删；只有跨着界线的那一天要逐个文件看。
- **转成长期保留**是一次改名（`cache/…` → `kept/…`）：同一个磁盘上的改名要么成了、要么没动，不会出现半个文件。
- **以前的版本**把检测图像存在内容仓库里（编号是内容哈希）。那些不搬：旧记录的图像照旧能看，算作长期保留。

## 4. 什么时候清

| 程序 | |
|---|---|
| `vision-runtime`、`vision-line serve`（长时间运行） | 启动时清一次，之后每小时一次，在后台线程里 |
| `vision-cli`、`vision-line` 的其他命令（跑完就退出） | 启动时清一次 |

清理不拿质量分析的锁：要删的文件可能很多，不能挡住检测。

**磁盘快满了的时候**：剩余空间低于 2 GB 时，没到期的缓存图像也清，从最旧的一天开始，直到够了或者缓存清空，并在日志里告警。
检测比“事后能看图”要紧——不能因为留图把磁盘写满，让检测记录都写不进去。长期保留的图像不在此列：清空了缓存还不够的话，日志里说“请清理磁盘”，由人处理。

## 5. 选项

| | |
|---|---|
| `--keep-images all`（默认） | M1 + M2：不合格的长期保留，合格的进短期缓存 |
| `--keep-images ng` | 只有 M1：合格的不留。磁盘小的机器可以用，代价是漏检无图可看 |
| `--keep-images none` | 都不留 |
| `--image-retention-hours <小时>` | 短期缓存留多久，默认 72；1 小时到 366 天之间 |

**磁盘大概要多少**：按一幅 300 KB、一天 5 万次检测算，72 小时的缓存约 45 GB；另外是长期保留的那些（不合格的、出错的、复判过的），它们只增不减。

## 6. 定下来的决定（2026-11-25 确认）

1. 保留期默认 72 小时。
2. 默认从“只留不合格的”改成“全留 + 过期清理”。升级之后磁盘占用会明显变大；不想要可以用 `--keep-images ng`。
3. 长期保留的图像不设上限、永久保留，和“检测记录永不删除”一致；以后和记录的清理策略一起做。
4. （实现时定的，请留意）**这个功能放在质量分析里，不在数据上下文里。** 设计（[05](05-tactical-design.md)）把图像缓存放在 BC-9 数据，由“采集策略”决定哪些转成样本。但产线运行平台上现在没有数据上下文，而检测图像和检测记录是一起产生、一起查看的。等产线一侧有了样本采集，再考虑挪过去。
5. （实现时定的，请留意）**以前存在内容仓库里的检测图像不搬、不清**：它们会一直留着。

## 7. 还没有的

- 长期保留的图像、检测记录的清理（留多少天）
- 采集策略：按比例抽样把合格的图像也收作样本
- 界面上显示“还有多久过期”、磁盘占用
- 清理的间隔、磁盘剩余空间的下限现在是写死的（1 小时、2 GB）
