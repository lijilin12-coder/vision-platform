## 1. 为什么需要

到这一步之前，一次检测交出来的只有：判定（OK / NG / ERROR）、判定依据（一句话，比如“亮斑 3 处，上限 0 处”）、每个节点的状态和耗时。

“亮斑 3 处”是给人看的。但下游要的是数据：

- 界面要把缺陷**画在图像上**——需要每个缺陷的位置和大小
- 统计要看某个尺寸这一周的**趋势**——需要每次检测的测量值，带名称和单位
- 一致性检查要比较两个平台的结果**差多少**——需要数值，不是一句话

这些信息其实在检测过程中都算出来了（连通块的位置、卡尺量的宽度、模板匹配的位姿），只是停在节点的输出端口上，检测结束就丢了。

## 2. 三种结果项

| | 是什么 | 字段 |
|---|---|---|
| 缺陷 `Defect` | 发现的一个具体问题 | 类别、中心位置、外接矩形、面积 |
| 测量值 `Measurement` | 某个测量项这一次的实测值 | 名称、数值、单位、允许的下限和上限、是否在范围内 |
| 位姿结果 `PoseResult` | 定位的结果 | 位姿、有没有找到、相似度 |

每个结果项都记着是哪个节点上报的。三种分开（术语表 Q-6 的决定）：它们的下游用途不同。

**和判定依据的关系**：判定依据回答“为什么合格 / 不合格”，决定判定；结果项是“发现了什么”，不决定判定。
一次合格的检测也可以有缺陷（个数没超上限）和测量值（在公差内）。

## 3. 谁来上报：知道含义的算子

关键的设计问题是：连通块什么时候算“缺陷”？

`vision.blob` 只知道它找到了一些连通块。它们可能是缺陷，也可能是要数的孔、要找的标记。
知道含义的是**后面那个判定算子**：`vision.judge_count` 的意思是“这些东西不该超过 N 个”，到了它这里，连通块才是缺陷，类别就是它的 `label` 参数。

所以规则是：**由知道含义的算子主动上报**，检测引擎不去猜。

| 算子 | 上报 | 说明 |
|---|---|---|
| `vision.judge_count` | 每个连通块一个缺陷 | 类别 = `label` 参数。不管判定合不合格都上报 |
| `vision.judge_range` | 一个测量值 | 名称 = `label`，单位 = `unit`，范围 = `min`～`max` |
| `vision.template_match` | 一个位姿结果 | 没找到也上报，标明没找到 |

写算子时用 `ctx.reportDefect(...)`、`ctx.reportMeasurement(...)`、`ctx.reportPose(...)`。这是输出端口之外的另一条通道：
端口是给**下游节点**用的，结果项是给**检测结果**用的。

**没有选的做法**：让检测引擎按端口类型自动收集（“凡是连到判定算子的连通块都算缺陷”）。
它不用改算子，但含义是猜的；类别、单位这些信息引擎也无从知道。

## 4. 不变量

`Inspection` 聚合新增一条：

| # | 规则 |
|---|---|
| **I5** | 结果项只能来自**执行成功**的节点 |

一个节点失败了，它在失败之前上报的东西不可信，不能进检测结果。被跳过的节点没有运行，自然也没有。
聚合在“完成”时检查每个结果项的来源；检测引擎只从成功的节点收集。两处都有，是因为聚合不应该相信调用它的人。

判定为 ERROR 的检测**可以**有结果项：来自失败之前已经成功的那些节点（比如定位成功了，后面的测量失败了）。

结果项和判定一样，只在完成时设置一次，之后不可修改（I3）。`InspectionCompleted` 事件里带着它们。

## 5. 坐标是哪个图像上的

缺陷的位置是**上报它的算子看到的图像**上的坐标。

方案里如果有“按位姿对齐”，对齐之后的节点看到的是转正、移回标准位置的图像，缺陷的坐标就是对齐后的坐标，**不是相机原图上的**。
把缺陷画回原图需要用位姿反算回去——**现在没有做**。结果里同时有位姿，信息是够的；等界面要在原图上画缺陷时再加。

## 6. 现在在哪里能看到

- 命令行：`inspect`、`recipe debug`、`station run` 的输出里，判定依据后面列出结果项（缺陷多时只列前 5 个）
- HTTP 接口：调试运行的回复里有 `result`：`defects`、`measurements`、`poses`（见 [dev/http-api.md](../dev/http-api.md)）
- 应用服务：`InspectionReport::result`

## 7. 没有做的

| 没有做 | 原因 |
|---|---|
| 缺陷的置信度（术语表里有） | 现在没有算子能给出置信度。等有分类模型时加 |
| 测量项 `MeasurementItem`（方案里定义“要测什么”：标称值、公差）| 现在测量值的名称和范围直接来自判定算子的参数，够用。要做跨方案的趋势统计时再把测量项提成方案里的一等概念 |
| 毫米单位、标定（规则 P4） | 没有标定。单位只是一段文字 |
| 异常检测算子上报缺陷 | 它只给出得分和异常图，没有“一个个缺陷”。异常图接“阈值 → Blob → 个数判定”就能得到带位置的缺陷 |
| 结果项的持久化、统计 | 检测记录现在不保存。属于 BC-6 结果与追溯（P1） |
| 把缺陷坐标换回原图 | 见 §5 |
| 一致性标准里按结果项比较（容差） | 基准图集现在只比较判定。属于 P1 的对比评估 |
