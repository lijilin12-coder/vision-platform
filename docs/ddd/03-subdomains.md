## 判断方法

1. **没有它行不行？** 不行 → 至少是支撑域。
2. **我们靠它赢吗？** 靠它赢 → 核心域；不靠 → 支撑域。
3. **有成熟的现成方案吗？** 有，而且不靠它赢 → 通用域，直接用。

## 子域清单

| 子域 | 类型 | 对应取胜因素 | 理由 | 投入策略 |
|---|---|---|---|---|
| **方案助手** | 🟥 核心域 | ① | 把视觉经验变成可以自动执行、自动验证的过程：套路、调参迭代、留出集、稳健性检查、报告。这是和同类拖拽式软件的主要差异 | 最认真设计，完整使用 DDD 战术模式 |
| **方案编排** | 🟥 核心域 | ① | 自由组合算子搭出检测方案。方案助手的基础：助手搭出来的就是普通的方案 | 同上 |
| **检测执行** | 🟥 核心域 | ② | 把方案跑起来、得出判定，并且在各平台上结果一致 | 同上 |
| **上线与热更新** | 🟥 核心域 | ② ④ | 上线包、一致性验证、部署、热切换、回滚。市面上很多视觉软件换方案都要停机 | 同上 |
| 模型工具链 | 🟨 支撑域 | ③ | 模型版本、模型契约、兼容判断、量化 → 转换 → 验证流水线需要自己做；量化和转换本身调用现成工具。闭环真正独特的环节在核心域里 | 自己做，简单够用 |
| 数据 | 🟨 支撑域 | ③ | 采集策略、样本、数据集、数据集版本；逻辑不复杂 | 自己做，简单够用 |
| 标注 | 🟨 支撑域 | ③ | 在检测结果和复判界面上直接标注，体验上和闭环紧密结合。**只做简单部分**：图像级标签、检测框；复杂的分割掩码标注支持按开源工具（CVAT、Label Studio）的格式导入导出，不自己做 | 自己做简单部分，复杂部分用现成工具 |
| 算子目录 | 🟨 支撑域 | ① | 注册表加元数据，必须有，但不是卖点 | 自己做，简单够用 |
| 标定 | 🟨 支撑域 | — | 测量必需，方法成熟 | 自己做，简单够用 |
| 结果统计 | 🟨 支撑域 | — | 批次、良率、误报和漏检统计；SPC 统计（P2） | 自己做，简单够用 |
| 视觉算法库 | 🟩 通用域 | — | 阈值、Blob、匹配、卡尺等基础算法；**我们靠“组合”赢，不靠单个算法赢**。算子只是对它们的封装 | 用 OpenCV（学习时可以手写一部分作为对照） |
| 推理运行时 | 🟩 通用域 | — | | ONNX Runtime、MindSpore Lite |
| 大模型 | 🟩 通用域 | — | 方案顾问的一种实现。我们靠“套路 + 循环 + 验证”赢，不靠某一个大模型赢 | 用现成的服务或模型，通过端口接入，可替换 |
| 量化和转换工具 | 🟩 通用域 | — | | ONNX Runtime 量化工具、MindSpore Lite 转换工具 |
| 图像采集驱动 | 🟩 通用域 | — | | 系统相机接口、社区库 |

## 说明

- 子域的分类**取决于我们靠什么赢**。如果以后转型做高精度测量产品，测量算法就会升级为核心域。
- 第 4 步划分限界上下文时，子域和上下文**不一定一一对应**：一个子域可能对应多个上下文，也可能多个小子域合并进一个上下文。
