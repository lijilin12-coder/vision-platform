# 17 复判

> 状态：已实现（2026-11-25）。属于 **BC-10 质量分析**，对应需求 QUA-01（漏检时从缓存找回图像那一半还没有，见 §5）。
> 术语见[术语表](02-glossary.md)：复判、检测记录、误报、漏检。

## 1. 要解决什么

系统判了 OK 或 NG，但系统会判错。**复判**是操作员事后确认：这一次实际上是合格还是不合格。

| 系统判的 | 人确认的 | 结论 |
|---|---|---|
| NG | 合格 | **误报**：把好的拦下来了 |
| OK | 不合格 | **漏检**：把坏的放出去了 |
| OK / NG | 和系统一样 | 系统判对了 |
| ERROR | 合格或不合格 | 系统当时没检测下来；人补上真实情况。不算误报也不算漏检 |

有了复判，才知道方案在产线上**实际**判得怎么样；判错的那些图像也是改进方案最有用的材料。

## 2. 模型

`Review`（`core/contexts/quality/domain/review.h`）：指向一条检测记录，写着系统当时的判定、人确认的真实情况、谁、什么时候、备注。

| 编号 | 规则 |
|---|---|
| R1 | 复判必须指向一条存在的检测记录 |
| R2 | 真实情况只有合格 / 不合格两种。ERROR 不是一种真实情况（和基准图集的真实判定是同一个道理） |
| R3 | 复判**只追加**。人可以改主意：再复判一次，以最近的一次为准；之前的那次留着 |
| R4 | 结论（判对 / 误报 / 漏检）由“系统的判定”和“真实情况”**算出来**，不由人另外填 |

**检测记录不因为复判而改**（Q1）。复判另外存一个文件，和检测记录放在同一个工位目录里：

```
<数据目录>/inspection-records/<工位 ID>/2026-11-25.jsonl     检测记录
<数据目录>/inspection-records/<工位 ID>/reviews.jsonl        复判，一行一条，只追加
```

**系统的统计也不因为复判而改**：汇总里“OK 多少、NG 多少、良率”还是系统当时判的；复判的数字另外列——复判了多少条，其中误报、漏检各多少。
两组数字不合在一起：复判通常只覆盖一部分记录，合在一起算出来的“真实良率”没有意义。

事件：复判确认是误判（误报或漏检）时发布 `MisjudgmentConfirmed`，带着工位、记录、种类、图像的内容哈希。

## 3. 复判的结果怎么回到方案上

这是复判的另一半用处（事件风暴里的规则 P3：“每当复判发现误判，就把图像收作样本”）。

现在用最直接的办法：**把复判过的图像导出成两个目录**。

```
station export-reviewed <工位ID> <目录> [--misjudged]
   → <目录>/ok/<记录编号>.png     人确认是合格的
   → <目录>/ng/<记录编号>.png     人确认是不合格的
```

这正是 `golden create --ok … --ng …` 和 `sample import --label …` 要的样子。于是有了一个完整的圈：

```
工位检测 → 检测记录 → 复判 → 导出 ok / ng → 建基准图集 → 验收新的方案 → 上线
```

用复判出来的图像建的基准图集去验收**当前**的方案，会正好暴露出那些误报和漏检（测试里验证了这一点）；改了方案之后再验收，就知道改好了没有。

文件名是检测记录的编号：不会重名，也能从一个文件找回是哪一次检测。

## 4. 怎么用

| 方式 | |
|---|---|
| 界面 | 工位页面的“历史记录”：点一条记录，点**实际合格**或**实际不合格**（可以写备注），自动跳到下一条。表格里多了“复判”一列；可以只看“还没复判的”“确认判错了的”；汇总里多了“已复判 n 条：误报 a，漏检 b”；可以把复判过的图像导出 |
| 命令行 | `station review <工位ID> <记录编号> ok\|ng [--note …] [--by …]`、`station records … [--unreviewed \| --misjudged]`、`station export-reviewed`、`station summary`。`vision-cli` 和 `vision-line` 都有 |
| HTTP | `POST /api/stations/{id}/records/{记录编号}/review`、`GET …/records?review=unreviewed\|misjudged`、`POST …/export-reviewed`；`…/summary` 里带复判的数字 |

## 5. 漏检的图像（F-3，只解决了一半）

默认只留不合格的和出错的图像。**判 OK 的没有图像**——而漏检恰恰是判了 OK 的那些。所以默认设置下：

- 漏检**可以复判**（操作员从下道工序知道是哪一个零件有问题），结论会记下来、算进统计
- 但**没有图像**：界面上看不到，也导不出来。导出时会说“另有 n 条复判过的记录当时没有留图像”，不会悄悄少掉

现在的办法是一个选项：`--keep-images all`（三个程序都有），所有检测的图像都留。代价是磁盘：一幅图像几百 KB，一天几万次检测就是十几 GB，而且**现在没有清理**。

设计里的办法是**短期图像缓存**（[05](05-tactical-design.md) §BC-9：所有图像留 72 小时，过期清掉，被复判或者被采集的转成长期保存）。它需要先有“删除不再被引用的内容”这个能力，还没有做。

## 6. 请确认的决定

1. **复判不改检测记录，也不改系统的统计**；复判的数字另外列（§2）。
2. **复判可以改，以最近一次为准；每一次都留着**（R3）。
3. **复判的结果靠“导出成两个目录”回到方案构建那一侧**（§3），没有做成自动的（事件 `MisjudgmentConfirmed` 已经发了，但还没有谁订阅它去自动建样本）。原因：产线运行平台上没有“数据”这个上下文；两个平台之间现在只有文件这一种传递方式。
4. **谁复判的只是一个可以不填的文字**——现在没有登录，没法确认是谁。
5. **漏检的图像默认找不回来**；想找回来要用 `--keep-images all`，而且磁盘要自己看着（§5）。
6. **ERROR 的记录复判后单独算一类**（“系统当时出错”），不算误报也不算漏检。

## 7. 还没有的

- 短期图像缓存和清理（§5）
- 复判时标出缺陷在哪里、是哪一种（现在只有合格 / 不合格）
- 误判自动成为待标注的样本；样本包（把图像连同来源和复判结果带到方案构建平台）
- 质量偏离告警（误报率突然升高）、批次、SPC
- 按时间段、按上线包看误报率和漏检率
