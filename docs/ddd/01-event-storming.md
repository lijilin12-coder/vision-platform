## C. 方案发布、上线包与部署

> 依据 H-08 的决定：**方案声明模型依赖（模型 ID + 兼容范围），上线包锁定具体版本**。上线包是验证、热更新和回滚的最小单位。

## 🟪 规则（每当……就……）

| # | 规则 |
|---|---|
| P1 | 每当**检测已完成**，就按**采集策略**决定是否保存图像（→ E2） |
| P2 | 每当**检测已完成**，如果属于某个批次，就更新批次统计 |
| P3 | 每当**复判发现误判**，就把图像加入“待标注”数据集（→ E4） |
| P4 | 每当**模型已导入**，就自动依次执行量化 → 转换 → 验证（F3 → F4 → F6） |
| P5 | 每当**上线包已创建**，就在基准平台上运行验收检查（→ C6）；验收通过后，在其他目标平台上运行一致性检查（→ C7） |
| P6 | 每当**上线包已就绪**，就在下一次检测开始前切换（→ G4） |
| P7 | 每当**切换后连续 N 次检测出现 ERROR**，就自动回滚到上一个上线包（→ G6） |
| P8 | 每当**工位启动**，就加载上次生效的上线包并预热模型（→ G1、G2） |
| P9 | 每当**新的模型版本已发布**，且在某个方案声明的兼容范围内，就提示可以为该方案创建新的上线包 |
| P10 | 每当**热切换**发生，就开启观察窗口；窗口内 NG 率偏离超过阈值则告警（→ G9） |
| P11 | 每当**手动回滚并选择撤回**，就撤回出问题的上线包（→ C11） |
| P12 | 每当**检测已完成**，就把图像放入短期缓存；超过保留期自动清理（→ E9） |
| P13 | 每当**复判确认漏检**，就从缓存找回图像，加入待标注数据集（→ E10、E4） |
| P17 | 每当**训练任务已完成**，就把模型文件导入模型仓库，成为未发布的模型版本，来源记为这次训练任务和数据集版本（→ F1，随后触发 P4） |
| N1 | **留作基准的样本永远不用于训练**：冻结基准图集、冻结数据集版本、提交训练任务时都要检查；按图像内容判断是否是同一个样本 |
| P14 | 每当**提议已提出**，就先检查，合法才应用（→ H4），否则拒绝并把原因告诉顾问（→ H3）；被拒绝的一轮也计入预算 |
| P15 | 每当**实验已完成**，就和此前最好的评估比较，决定保留（→ H6）还是回退（→ H7） |
| P16 | 每当**助手会话已结束**，就对最好的候选方案做盲测集评估和稳健性检查，然后生成报告（→ H9、H10、H11） |

## 🟫 外部系统

| 外部系统 | 交互 |
|---|---|
| 图像源（相机、文件夹） | 提供图像 |
| 外部训练平台 | 接收导出的数据集，交回训练好的 ONNX 模型（手工导出、导入的方式仍然保留） |
| 训练后端（自有的训练服务，或外部的训练平台） | 执行训练任务，由模型训练上下文通过端口调用 |
| 模型量化和转换工具（ONNX Runtime 量化工具、MindSpore Lite 转换工具） | 由模型工具链调用 |
| PLC / MES | 本阶段范围外，预留 |
| 大模型服务（云端、局域网或本机） | 作为“方案顾问”的一种实现，由方案助手通过端口调用；只在编辑方案时使用，产线运行不依赖它 |
